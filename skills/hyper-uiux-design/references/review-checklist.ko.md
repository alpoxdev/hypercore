# 검토 체크리스트

이미지가 돌아오면 검토할 때마다 이 참조를 읽습니다. 생성한 화면 시안에서 무엇을 점검하는지, 항목을 어떻게 기록하는지, 어떤 이미지가 승인 후보가 되는지를 적습니다.

## 1. 기록 방법

반환된 이미지를 열어서 직접 봅니다. 도구 호출이 성공했다는 것은 검토가 아닙니다. 항목마다 한 행을 기록합니다.

| 열 | 내용 |
|---|---|
| Item | 아래 id로 적은 점검 |
| Result | `pass`, `fail`, `not checkable in an image` 중 하나 |
| Label | `seen` 또는 `computed` |
| Note | 관찰한 것을 몇 단어로. `fail`이면 다음 브리프가 바꿀 것 |

`not checkable in an image` 항목은 인계에 요구사항으로 옮겨 적습니다. 통과로 세지 않습니다.

## 2. 브리프 충실도

| Id | 점검 |
|---|---|
| F1 | 브리프의 모든 영역이 밝힌 순서대로 있다 |
| F2 | 단 하나의 주 동작이 밝힌 자리에 강조색으로 있다 |
| F3 | 컴포넌트가 이름을 적은 것과 같다. 여분의 탭 바, 배너, 카드, 단계가 없다 |
| F4 | 캔버스 방향과 플랫폼 프레임이 일치한다. 모바일은 시스템 바가 있고, 웹은 요청이 없으면 브라우저 틀이 없다 |
| F5 | 테마가 브리프의 토큰 열과 일치한다. 배경, 표면, 강조가 밝힌 색으로 읽힌다 |
| F6 | 화면이 평평하고 정면이며 가장자리까지 차 있고, 둘레에 기기, 손, 장면이 없다 |

## 3. 가독성

| Id | 점검 |
|---|---|
| R1 | 렌더링된 문자열이 한글 음절 하나하나까지 브리프와 한 글자씩 일치하고 한 번씩 나온다 |
| R2 | 나열한 문자열 밖에 읽을 수 있는 글자가 없다. 다른 글자는 중립 막대다 |
| R3 | 위계가 제목, 내용, 주 동작 순서로 읽힌다 |
| R4 | 글자가 겹치거나 가장자리에서 잘리거나 아이콘과 부딪히지 않는다 |
| R5 | 가장 작은 글자도 이미지 원래 크기에서 읽힌다 |

## 4. 생성 이미지 티

시안을 기계가 만든 것처럼 보이게 하는 표시이고, 구현자를 잘못된 방향으로 이끕니다.

| Id | 점검 |
|---|---|
| G1 | 지어낸 로고, 브랜드 이름, 마스코트, 앱 아이콘이 없다 |
| G2 | 토큰에 없는 장식이 없다. 그라데이션 번짐, 빛 번짐, 유리 흐림, 떠다니는 덩어리, 스톡 풍 일러스트가 해당한다 |
| G3 | 진짜처럼 꾸민 가짜 데이터가 없다. 브리프가 요청하지 않은 큰 통계, 후기, 평점, 이름이 해당한다 |
| G4 | 아이콘이 한 스타일, 한 굵기이고 각각 실제 컨트롤이 있을 자리에 있다 |
| G5 | 간격이 규칙적이다. 같은 종류의 항목 사이 간격이 같고, 좌우 여백이 하나이며, 가장자리가 정렬돼 있다 |
| G6 | 반복되는 컴포넌트의 모양이 같다. 모든 카드, 행, 입력란이 형제와 일치한다 |
| G7 | 중복되거나 반쯤 그려진 요소가 없고 같은 이미지에 두 번째 화면이 없다 |

## 5. 접근성

| Id | 점검 | 라벨 |
|---|---|---|
| A1 | 토큰의 글자와 배경 쌍이 각각 대비 최소 기준을 충족한다 | `computed` |
| A2 | 사진이나 그라데이션 위의 글자 뒤에 단색이나 스크림 층이 있다 | `seen` |
| A3 | 상태를 색만으로 전달하지 않는다 | `seen` |
| A4 | 컨트롤이 플랫폼의 대상 크기를 충족할 만큼 크게 그려져 있다. 정확한 크기는 인계 요구사항이다 | `not checkable in an image` |
| A5 | 포커스, 스크린 리더 이름, 키보드 순서 | `not checkable in an image` |

A1을 위해 이미지에서 색을 추출하지 않습니다. 비율은 토큰 값에서 나옵니다.

## 6. 세트 일관성

이미지마다 따로 통과한 뒤에 세트의 모든 이미지에 함께 적용합니다.

| Id | 점검 |
|---|---|
| S1 | 배경, 표면, 강조가 모든 화면에서 같아 보인다 |
| S2 | 글자 처리가 같다. 서체 성격이 하나이고 제목과 본문 크기 체계가 같다 |
| S3 | 공통 컴포넌트가 모든 화면에서 같다. 버튼 모양과 높이, 입력란 모양, 카드 모서리가 해당한다 |
| S4 | 시스템 바와 내비게이션이 같은 자리에 같은 스타일로 있다 |
| S5 | 한 화면의 라이트와 다크 버전은 색만 다르다 |

흔들린 화면은 흔들린 불변 요소를 다시 적어 재생성합니다. 기준 화면을 그 화면에 맞춰 바꾸지 않습니다.

## 7. 레퍼런스 독립성

| Id | 점검 |
|---|---|
| I1 | 시안이 어느 한 레퍼런스로 오인되지 않는다. 구도는 베껴 그린 것이 아니라 패턴 요약에서 만들었다 |
| I2 | 참고한 제품의 이름, 로고, 일러스트, 문구, 고유한 색·서체 조합이 나오지 않는다 |
| I3 | 브리프에 제품 이름, 레퍼런스 URL, 레퍼런스 이미지가 없다 |

## 8. 판정

- 후보: 2절부터 7절까지 `fail`이 없습니다.
- 재생성: `fail`이 하나라도 있고 그 화면에 상한 안의 브리프가 남아 있습니다. 다음 브리프는 한 가지를 바꾸며, 실패한 절 가운데 다음 순서에서 가장 앞선 것을 고릅니다. 레퍼런스 독립성, 브리프 충실도, 가독성, 생성 이미지 티, 세트 일관성 순서입니다.
- 정지: 상한에 닿았습니다. 실패 항목이 가장 적은 시도를 남기고 그 항목을 나열합니다.

후보는 승인된 시안이 아닙니다. 승인은 사용자의 몫입니다.
