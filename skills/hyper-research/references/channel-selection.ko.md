# 채널 선택

증거 채널을 고르고 질의 계획을 작성할 때 이 참고 파일을 사용합니다.

## 주제별 채널 매핑

| 주제 형태 | 시작 채널 | 필요할 때 추가 | 피할 것 |
|------|------|------|------|
| 내부 프로젝트 동작이나 이력 | 로컬 저장소 검색 | 저장소 메타데이터가 중요하면 git 이력이나 GitHub 근거 | 시작부터 라이브 웹 검색 |
| 라이브러리나 패키지 사용법 | 사용할 수 있는 문서나 fetch 역량으로 확인하는 해당 버전 공식 문서 | GitHub 이슈, 릴리스, 예제 | 문서보다 일반 블로그 우선 |
| 제품, 저장소, 릴리스 비교 | GitHub 릴리스, 이슈, 변경로그, 코드 검색 | 독립적 해설을 위한 라이브 웹 보도 | 마케팅 페이지만 믿기 |
| 시장, 추세, 시사 조사 | 날짜를 인식하는 라이브 웹 검색 | 공식 보고서나 기업 공시 | 오래된 에버그린 글 |
| 학술이나 개념 조사 | 1차 논문이나 공식 레퍼런스 | 종합을 위한 2차 해설 | 의견글을 1차 근거로 쓰기 |
| 다중 옵션 기술 비교 | 각 옵션의 공식 문서, 그다음 독립 벤치마크나 사례 | 구현 현실을 보여 주는 GitHub 근거 | 기준표 없는 결론 |

## 선택 메모

- 질문을 충분히 답할 수 있는 가장 작은 채널 집합을 우선합니다.
- 요청이 최신이거나 최근이거나 날짜에 민감하면 라이브 검색을 씁니다.
- 코드베이스만 다루는 질문은 외부 근거가 명시적으로 필요할 때만 저장소 밖으로 나갑니다.
- 패키지 버전이 지정되면 그 버전의 공식 문서에서 시작합니다.
- 원본 파일(PDF, JSON, 피드, 사이트맵)은 직접 가져옵니다. fetch가 읽지 못하는 렌더링 페이지는 브라우징 역량이 있으면 그것으로 열고, 없으면 접근 불가로 기록합니다.

## 검색 기법

- 먼저 영어로 검색합니다. 대부분 엔진, 코드 호스트, 문서 사이트에서 가장 큰 코퍼스이기 때문입니다. 주제가 지역적이거나 사용자가 출처 언어를 지정하면 그 뒤에 해당 언어 검색을 덧붙입니다.
- 질의마다 연산자나 관점을 바꿉니다. 같은 질의를 두 번 쓰면 한 번의 기회를 낭비합니다. 연산자 지원은 엔진마다 다르므로, 지원되지 않는 연산자는 실패가 아니라 표현을 바꾸라는 신호로 봅니다.

| 연산자 | 예 | 용도 |
|---|---|---|
| `site:` | `site:github.com <주제>` | 도메인 제한 |
| `filetype:` | `filetype:pdf <주제> survey` | 논문과 사양서 |
| `intitle:` / `inurl:` | `intitle:benchmark <주제>` | 표적 페이지 |
| `"exact"` / `-term` | `"<정확한 구절>" -tutorial` | 정확도와 제외 |
| `OR` | `<a> OR <b> <주제>` | 범위 확대 |
| `before:` / `after:` | `<주제> after:<YYYY-MM-DD>` | 최신성 제어 |

- 수확이 큰 관점: 공식 문서(`site:<docs domain>`), 구현(`site:github.com`), 변경로그(`changelog OR "release notes" <version>`), 대안(`vs OR alternative OR comparison`), 반대 근거(`<claim> problems OR criticism OR regression`). 반대 근거 검색은 claim gate의 반대 검색도 겸합니다.
- 사이트맵(`<base>/sitemap.xml`)으로 URL을 추측하지 않고 올바른 공식 페이지를 찾습니다.
