# Post Type Library

> Korean version: [`post-type-library.ko.md`](post-type-library.ko.md)

**Purpose**: The business-blog post types and the section order each one uses. [`../rules/post-workflow.md`](../rules/post-workflow.md) §2 picks one primary type here; this file supplies the shape it then fills. A type is a content format, not a commercial category — the commercial relationship stays in the mode line that `post-workflow.md` §0 derives.

## 0. How to use

Read §1 and the §2 index to pick the type. Then read **only** the §3 playbook of the chosen type, plus the playbooks of a secondary type when §2 picked one. Nothing else in this file is needed for a normal run.

## 1. The three axes

Three axes decide a post, and they are independent.

1. **Customer intent** — what the searcher is doing: 알아보기 (learning), 비교하기 (comparing), 믿을 만한지 확인하기 (checking whether to trust), 구매하기 (buying).
2. **Post format** — the shape of the content, which is what §2 names.
3. **Business goal** — 유입, 신뢰, 문의, 예약, 구매, 재방문.

One post can carry more than one nature without carrying more than one type. Write the combination as `주 유형=문제 해결형 / 보조=비교·선택 기준형 / 목표=문의 / 모드=전환형` and do not invent type names outside the index.

## 3. Type playbooks

### 1. 문제 해결형

- **언제 쓰는가**: the reader can name the problem in their own words and searches for the cause or the fix.
- **스켈레톤**: 상황·증상 → 원인 후보 → 해결 단계 → 비용·기간 → 안 되는 경우 → 다음 단계.
- **수치가 붙는 자리**: each solution step carries the interval, amount, or duration it uses.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: no disclosure when nothing is promoted; a 전환형 run discloses in the opening and closes with one CTA.
- **흔한 실패**: listing causes with no way to tell them apart; steps with no number attached.

### 2. 체크리스트·템플릿형

- **언제 쓰는가**: the reader wants to do the thing now and needs the sequence.
- **스켈레톤**: 이걸 쓰는 순간 → 준비물 → 단계 체크리스트 → 빠뜨리기 쉬운 것 → 다음에 할 일.
- **수치가 붙는 자리**: the checklist items that have a threshold, a quantity, or a timing.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: same as 문제 해결형; a template the business owns is disclosed like any other offer.
- **흔한 실패**: items that are categories rather than actions; a list with no order.

### 3. 비교·선택 기준형

- **언제 쓰는가**: the reader is choosing between named options.
- **스켈레톤**: 무엇을 고르는지 → 기준 → 기준별 비교 → 상황별 추천 → 안 맞는 선택.
- **수치가 붙는 자리**: the comparison table, one column per sourced option.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: disclose when one of the compared options is the author's own; never rank it above another practitioner's (R10 boundary in the medical reference).
- **흔한 실패**: an unsourced comparison table; a second option invented to look balanced.

### 4. 후기·리뷰형

- **언제 쓰는가**: someone genuinely used it and can report what happened.
- **스켈레톤**: 무엇을 왜 썼는지 → 쓰기 전 상태 → 사용 과정 → 결과 → 아쉬운 점 → 다시 쓴다면.
- **수치가 붙는 자리**: the result the experience produced, with the timeframe it took.
- **register 행**: 경험·후기·일상 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: disclosure is mandatory whenever the author has a relationship with the product; a review of the author's own product still discloses.
- **흔한 실패**: an experience the author never had; a verdict with no downside.

### 5. 고객 성공 사례형

- **언제 쓰는가**: one real customer's situation and result can be told.
- **스켈레톤**: 고객 상황 → 맡긴 이유 → 진행 과정 → 측정 가능한 결과 → 같은 상황이면.
- **수치가 붙는 자리**: the measurable result, with its baseline and timeframe.
- **register 행**: 전문·서비스 in both cases.
- **고지·CTA**: disclose the relationship; the customer's consent is the author's responsibility, and an unavailable case stays a slot.
- **흔한 실패**: a case with no baseline; a testimonial that promises an outcome (banned in medical work).

### 6. FAQ·반론 해소형

- **언제 쓰는가**: the same questions keep blocking the decision.
- **스켈레톤**: 질문 → 결론 먼저 → 이유·근거 → 예외 조건 → 관련 질문.
- **수치가 붙는 자리**: the first sentence of each answer, as the condition and its exception.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: none for a neutral FAQ; a 전환형 FAQ still discloses and keeps one CTA.
- **흔한 실패**: questions nobody asks; an answer that restates the question.

### 7. 현장·프로세스 공개형

- **언제 쓰는가**: the process itself is the evidence and can be shown.
- **스켈레톤**: 작업 전 상태 → 순서대로 단계 → 시간·사람·장비 → 변수와 지연 → 문의 시 준비.
- **수치가 붙는 자리**: the time, the number of people, the equipment, the cost basis.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: disclose the relationship; photos of the author's own site are real material, never generated.
- **흔한 실패**: describing a process the author does not run; a stage with no duration.

### 8. 인터뷰·전문가형

- **언제 쓰는가**: a named practitioner's view is the reason to read.
- **스켈레톤**: 누구를 왜 → 핵심 주장 → 근거 → 반대 관점 → 실무 적용.
- **수치가 붙는 자리**: the figures the interviewee stated, attributed to them.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: the relationship between the author and the interviewee is disclosed when it exists.
- **흔한 실패**: quotes nobody said; an expert whose scope does not cover the claim.

### 9. 트렌드·업계 해석형

- **언제 쓰는가**: a change means the reader must re-decide.
- **스켈레톤**: 무엇이 바뀌었는지 → 확인된 사실과 날짜 → 업종에 미치는 영향 → 대응 → 확인할 것.
- **수치가 붙는 자리**: the dated figures of the change, each with its source and date.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: none for interpretation; a forecast is labeled as a forecast.
- **흔한 실패**: treating a rumor as a change; an undated trend claim.

### 10. 브랜드 스토리·비하인드형

- **언제 쓰는가**: the reason the business works this way is itself useful to the reader.
- **스켈레톤**: 시작 계기 → 과정의 어려움 → 선택과 실패 → 지금의 기준 → 독자에게 의미.
- **수치가 붙는 자리**: the concrete markers (years, counts, the one decision that changed the process).
- **register 행**: 비상업은 내용에 따라 정보·비교·가이드 또는 경험·후기·일상; 전환형은 전문·서비스.
- **고지·CTA**: own-business disclosure applies; a neutral close is the default unless the goal is a booking.
- **흔한 실패**: a timeline with no decision in it; a story that ends in a sales line.

### 11. 제품·서비스 소개형

- **언제 쓰는가**: the reader needs to know what the thing does and whether it fits them.
- **스켈레톤**: 어떤 상황에 필요한지 → 무엇을 하는지 → 구성·사양·조건 → 비용·기간 → 안 맞는 경우.
- **수치가 붙는 자리**: the specification, price basis, and duration of the thing being introduced.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: disclose; brand lines stay verbatim; claims the material does not support stay slots.
- **흔한 실패**: an unconditional recommendation; specifications with no scope.

### 12. 프로모션·오퍼형

- **언제 쓰는가**: a dated offer with conditions must be stated exactly.
- **스켈레톤**: 조건과 기간 → 대상 → 신청 방법 → 제외 조건 → 남은 자리.
- **수치가 붙는 자리**: the price basis, the period, and the eligibility limit.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: disclose; the CTA is exactly one and phrased as the reader's decision. In medical work, a discount or fee-waiver CTA is blocked until the legal boundary is confirmed.
- **흔한 실패**: an invented deadline; a benefit with no exclusion clause.

## 4. Common formula

Every playbook sits inside one contract: **one customer situation → the answer early → real evidence → conditions and limits → the next action.** A title follows `[대상 또는 지역] + [구체적인 문제] + [원하는 결과 또는 선택 기준]`. These are this skill's writing defaults, not Naver rules.

## 5. Buyer journey → type

The stage fixes the candidate types; the search-intent slice stays a single slice (R1) whichever type is chosen.

| Stage | What the reader is doing | Candidate types |
|---|---|---|
| 발견 | Meeting the problem | 문제 해결형 · 트렌드·업계 해석형 |
| 탐색 | Learning how it is solved | 문제 해결형 · 체크리스트·템플릿형 · FAQ·반론 해소형 |
| 비교 | Weighing options | 비교·선택 기준형 · 제품·서비스 소개형 · 후기·리뷰형 |
| 검증 | Deciding whom to trust | 고객 성공 사례형 · 현장·프로세스 공개형 · 인터뷰·전문가형 · 브랜드 스토리·비하인드형 |
| 결정 | Acting now | 프로모션·오퍼형 · 제품·서비스 소개형 |
| 재이용 | Returning | 후기·리뷰형 · FAQ·반론 해소형 · 현장·프로세스 공개형 |

This mapping is **this skill's own classification**, not a Naver rule and not an observed default.

Alias map for names used in other material: 가이드형 → 문제 해결형, 업계 해석형 → 트렌드·업계 해석형, 오퍼형 → 프로모션·오퍼형, 가격·조건 FAQ and 상세 서비스 안내 → FAQ·반론 해소형, 사용법 → 문제 해결형. Only the index names are canonical.

## 6. What this library does not do

- It does not plan a publishing sequence, an industry-by-industry combination, or a first-ten-post allocation. This skill writes one post per request (R7).
- It is not a ranking rule. A type does not make a post rank, and no type is "favored" by Naver.
- It does not replace R1. The single intent slice is chosen in `post-workflow.md` §2 from the search result, before the type is picked.
- It does not set the commercial relationship. The mode in `post-workflow.md` §0 and the disclosure rule in R6 do that.
