## 0. 사용 방식

§1과 §2 색인으로 유형을 고릅니다. 그다음 **고른 유형의** §3 플레이북만 읽고, §2에서 보조 유형을 골랐으면 그 플레이북까지 읽습니다. 일반적인 실행에서 이 파일의 나머지는 필요하지 않습니다.

## 1. 세 축

글을 결정하는 세 축은 서로 독립입니다.

1. **고객 의도** — 검색하는 사람이 지금 하는 일: 알아보기, 비교하기, 믿을 만한지 확인하기, 구매하기.
2. **게시글 형식** — 콘텐츠의 모양. §2가 이름 붙이는 것이 이것입니다.
3. **사업 목표** — 유입, 신뢰, 문의, 예약, 구매, 재방문.

한 글이 여러 성격을 가질 수는 있어도 유형을 여러 개 갖지는 않습니다. 조합은 `주 유형=문제 해결형 / 보조=비교·선택 기준형 / 목표=문의 / 모드=전환형`처럼 적고, 색인에 없는 유형 이름을 만들지 않습니다.

## 3. 유형 플레이북

### 1. 문제 해결형

- **언제 쓰는가**: 독자가 문제를 자기 말로 짚고 원인이나 해결을 검색합니다.
- **스켈레톤**: 상황·증상 → 원인 후보 → 해결 단계 → 비용·기간 → 안 되는 경우 → 다음 단계.
- **수치가 붙는 자리**: 해결 단계마다 그 단계가 쓰는 간격·양·기간.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: 홍보 대상이 없으면 공개 문장도 없습니다. 전환형이면 서두에 공개하고 끝에 행동 유도 하나.
- **흔한 실패**: 구분할 방법 없는 원인 나열, 숫자 없는 단계.

### 2. 체크리스트·템플릿형

- **언제 쓰는가**: 독자가 지금 하려 하고 순서가 필요합니다.
- **스켈레톤**: 이걸 쓰는 순간 → 준비물 → 단계 체크리스트 → 빠뜨리기 쉬운 것 → 다음에 할 일.
- **수치가 붙는 자리**: 기준값·수량·시점이 있는 항목.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: 문제 해결형과 같습니다. 사업체가 소유한 템플릿은 다른 제안과 같은 방식으로 공개합니다.
- **흔한 실패**: 행동이 아니라 분류인 항목, 순서 없는 목록.

### 3. 비교·선택 기준형

- **언제 쓰는가**: 독자가 이름 있는 선택지 사이에서 고릅니다.
- **스켈레톤**: 무엇을 고르는지 → 기준 → 기준별 비교 → 상황별 추천 → 안 맞는 선택.
- **수치가 붙는 자리**: 비교표. 출처 있는 선택지마다 한 열.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: 비교 대상 중 하나가 작성자 것이면 공개합니다. 다른 의료인의 것보다 우위로 배치하지 않습니다(의료 reference의 법적 경계).
- **흔한 실패**: 출처 없는 비교표, 균형을 맞추려고 만든 둘째 선택지.

### 4. 후기·리뷰형

- **언제 쓰는가**: 실제로 써 본 사람이 있었던 일을 말할 수 있습니다.
- **스켈레톤**: 무엇을 왜 썼는지 → 쓰기 전 상태 → 사용 과정 → 결과 → 아쉬운 점 → 다시 쓴다면.
- **수치가 붙는 자리**: 그 경험이 만든 결과와 걸린 기간.
- **register 행**: 경험·후기·일상 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: 작성자가 그 제품과 관계가 있으면 공개는 필수입니다. 자기 제품 후기도 공개합니다.
- **흔한 실패**: 하지 않은 경험, 아쉬운 점 없는 총평.

### 5. 고객 성공 사례형

- **언제 쓰는가**: 실제 고객 한 명의 상황과 결과를 말할 수 있습니다.
- **스켈레톤**: 고객 상황 → 맡긴 이유 → 진행 과정 → 측정 가능한 결과 → 같은 상황이면.
- **수치가 붙는 자리**: 측정 가능한 결과와 기준선·기간.
- **register 행**: 두 경우 모두 전문·서비스.
- **고지·CTA**: 관계를 공개합니다. 고객 동의 확보는 작성자 책임이며, 쓸 수 있는 사례가 없으면 슬롯으로 남깁니다.
- **흔한 실패**: 기준선 없는 사례, 결과를 약속하는 체험담(의료에서는 금지).

### 6. FAQ·반론 해소형

- **언제 쓰는가**: 같은 질문이 계속 결정을 막습니다.
- **스켈레톤**: 질문 → 결론 먼저 → 이유·근거 → 예외 조건 → 관련 질문.
- **수치가 붙는 자리**: 답변 첫 문장. 조건과 그 예외로.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: 중립적인 FAQ에는 없습니다. 전환형 FAQ도 공개하고 행동 유도는 하나만 둡니다.
- **흔한 실패**: 아무도 묻지 않는 질문, 질문을 되풀이하는 답.

### 7. 현장·프로세스 공개형

- **언제 쓰는가**: 과정 자체가 증거이고 보여줄 수 있습니다.
- **스켈레톤**: 작업 전 상태 → 순서대로 단계 → 시간·사람·장비 → 변수와 지연 → 문의 시 준비.
- **수치가 붙는 자리**: 시간, 인원, 장비, 비용 기준.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: 관계를 공개합니다. 자기 현장 사진은 실제 자료이며 생성 그림으로 대체하지 않습니다.
- **흔한 실패**: 작성자가 하지 않는 과정 설명, 소요 시간 없는 단계.

### 8. 인터뷰·전문가형

- **언제 쓰는가**: 이름 있는 실무자의 관점이 읽을 이유입니다.
- **스켈레톤**: 누구를 왜 → 핵심 주장 → 근거 → 반대 관점 → 실무 적용.
- **수치가 붙는 자리**: 인터뷰이가 말한 수치. 그 사람에게 귀속시켜 씁니다.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: 작성자와 인터뷰이의 관계가 있으면 공개합니다.
- **흔한 실패**: 하지 않은 말 인용, 그 주장을 감당하지 못하는 전문 분야의 전문가.

### 9. 트렌드·업계 해석형

- **언제 쓰는가**: 변화 때문에 독자가 다시 판단해야 합니다.
- **스켈레톤**: 무엇이 바뀌었는지 → 확인된 사실과 날짜 → 업종에 미치는 영향 → 대응 → 확인할 것.
- **수치가 붙는 자리**: 그 변화의 날짜 있는 수치. 각각 출처와 날짜와 함께.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: 해석에는 없습니다. 전망은 전망이라고 밝힙니다.
- **흔한 실패**: 소문을 변화로 취급, 날짜 없는 흐름 주장.

### 10. 브랜드 스토리·비하인드형

- **언제 쓰는가**: 사업을 이렇게 하는 이유 자체가 독자에게 쓸모가 있습니다.
- **스켈레톤**: 시작 계기 → 과정의 어려움 → 선택과 실패 → 지금의 기준 → 독자에게 의미.
- **수치가 붙는 자리**: 구체적 표지(연차, 횟수, 과정을 바꾼 그 결정).
- **register 행**: 비상업은 내용에 따라 정보·비교·가이드 또는 경험·후기·일상; 전환형은 전문·서비스.
- **고지·CTA**: 자사 공개가 적용됩니다. 목표가 예약이 아니면 중립적 마무리가 기본입니다.
- **흔한 실패**: 결정이 없는 연표, 판매 문장으로 끝나는 이야기.

### 11. 제품·서비스 소개형

- **언제 쓰는가**: 그것이 무엇을 하고 자신에게 맞는지를 독자가 알아야 합니다.
- **스켈레톤**: 어떤 상황에 필요한지 → 무엇을 하는지 → 구성·사양·조건 → 비용·기간 → 안 맞는 경우.
- **수치가 붙는 자리**: 소개하는 것의 사양, 가격 기준, 기간.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: 공개합니다. 브랜드 문장은 원문 유지, 자료가 뒷받침하지 않는 주장은 슬롯으로 둡니다.
- **흔한 실패**: 조건 없는 추천, 범위 없는 사양.

### 12. 프로모션·오퍼형

- **언제 쓰는가**: 기간과 조건이 있는 제안을 정확히 밝혀야 합니다.
- **스켈레톤**: 조건과 기간 → 대상 → 신청 방법 → 제외 조건 → 남은 자리.
- **수치가 붙는 자리**: 가격 기준, 기간, 자격 조건.
- **register 행**: 정보·비교·가이드 (비상업) / 전문·서비스 (전환형).
- **고지·CTA**: 공개합니다. 행동 유도는 정확히 하나이고 독자의 결정으로 표현합니다. 의료에서는 법적 경계가 확인되기 전까지 할인·진료비 면제 CTA가 차단됩니다.
- **흔한 실패**: 만들어낸 마감, 제외 조건 없는 혜택.

## 4. 공통 공식

모든 플레이북은 한 계약 안에 들어갑니다. **고객 상황 1개 → 이른 답 → 실제 근거 → 조건과 한계 → 다음 행동.** 제목은 `[대상 또는 지역] + [구체적인 문제] + [원하는 결과 또는 선택 기준]`을 따릅니다. 이 둘은 이 스킬의 작성 기본값이며 네이버 규칙이 아닙니다.

## 5. 구매 여정 → 유형

단계가 후보 유형을 정합니다. 어떤 유형을 고르든 검색 의도 슬라이스는 하나로 유지됩니다(R1).

| 단계 | 독자가 하는 일 | 후보 유형 |
|---|---|---|
| 발견 | 문제를 만남 | 문제 해결형 · 트렌드·업계 해석형 |
| 탐색 | 어떻게 푸는지 알아봄 | 문제 해결형 · 체크리스트·템플릿형 · FAQ·반론 해소형 |
| 비교 | 선택지를 저울질 | 비교·선택 기준형 · 제품·서비스 소개형 · 후기·리뷰형 |
| 검증 | 누구를 믿을지 판단 | 고객 성공 사례형 · 현장·프로세스 공개형 · 인터뷰·전문가형 · 브랜드 스토리·비하인드형 |
| 결정 | 지금 행동 | 프로모션·오퍼형 · 제품·서비스 소개형 |
| 재이용 | 다시 찾음 | 후기·리뷰형 · FAQ·반론 해소형 · 현장·프로세스 공개형 |

이 매핑은 **이 스킬 자체의 분류**이며, 네이버 규칙도 observed 기본값도 아닙니다.

다른 자료에서 쓰는 이름의 정규화: 가이드형 → 문제 해결형, 업계 해석형 → 트렌드·업계 해석형, 오퍼형 → 프로모션·오퍼형, 가격·조건 FAQ·상세 서비스 안내 → FAQ·반론 해소형, 사용법 → 문제 해결형. 정식 이름은 색인의 이름뿐입니다.

## 6. 이 라이브러리가 하지 않는 것

- 발행 순서, 업종별 조합, 첫 10편 배분을 계획하지 않습니다. 이 스킬은 요청 하나에 글 한 편을 씁니다(R7).
- 랭킹 규칙이 아닙니다. 유형이 글을 상위로 올리지 않으며, 네이버가 특정 유형을 "선호"하지도 않습니다.
- R1을 대체하지 않습니다. 단일 의도 슬라이스는 유형을 고르기 전에 `post-workflow.md` §2에서 검색 결과를 보고 정합니다.
- 상업적 관계를 정하지 않습니다. `post-workflow.md` §0의 모드와 R6의 공개 규칙이 정합니다.
