# Naver Blog Maker

> 네이버의 현행 시스템이 노출할 수 있고, 검색한 사람이 클릭해서 끝까지 읽고, 독자가 사람이 직접 쓴 글로 받아들이는 네이버 블로그 글 한 편을 씁니다.

<output_language>

사용자 대면 결과물(제목 후보, 이미지·슬롯 마커가 든 글 블록, 해시태그, 메모, 자체 점검 요약)은 모두 한국어로 씁니다. 제품명, URL, 명령어, 파일 경로, 인용한 원문은 원형을 유지합니다. 다른 언어는 사용자가 요청할 때만 쓰며 그 요청은 보통 다른 스킬의 일입니다.

</output_language>

<purpose>

- 키워드에서 시작합니다. 검색어, 상위 글의 빈틈, 출처 있는 사실을 리서치한 뒤 초안을 씁니다. 사용자에게 사실 묶음을 먼저 요구하지 않습니다.
- 네이버가 공개한 규칙(출처의 주제 레인, 문서의 경험과 독창성, 의도 슬라이스 적합, 키워드 삽입 금지, 기만적 제목·링크 금지, 공개 의무)을 따르고 공식 제한 기준을 절대 건드리지 않는 글을 만듭니다.
- 사진이 들어갈 자리마다 무엇을 찍고 캡션이 무엇을 증명할지 적은 인라인 이미지 슬롯을 두고, 작성자만 아는 것은 지어내지 않고 `[확인 필요]` 슬롯으로 표시합니다.
- 선택한 양식으로 전달합니다. plain은 text 블록, rich는 제목·태그와 분리된 본문 HTML입니다.
- 제목에서 구체적인 약속으로 붙잡고 첫 화면 안에서 지킵니다. 낚시 어휘 대신 수정된 패턴 라이브러리를 씁니다.
- `rules/human-prose.ko.md`에 내장된 문장 규칙 아래에서 초안을 써서 처음부터 기계가 쓴 질감이 없게 합니다.
- 네이버가 말한 것(`official`), 실무자가 관찰한 것(`observed`), 속설을 구분하고 사용자가 "규칙"을 물으면 무엇이 무엇인지 말합니다.
- 두 모드를 지원합니다. 브랜드 없이 노출과 가독을 노리는 정보/경험형, 사용자의 가치입증 사실로 지정 브랜드의 문의나 방문을 만들어야 하는 전환형.
- 사용자가 이미 쓴 네이버 글을 수리합니다. 받은 어미와 내용 앵커를 지키고, 글을 다시 쓰는 대신 `rules/repair-method.ko.md`대로 기계가 쓴 질감을 걷어냅니다.
- `references/tell-catalog.ko.md`를 훑어 문장 패스를 심화합니다. 패밀리 표 뒤의 개별 패턴마다 나쁜 예·좋은 예와 지우는 W-ID가 있습니다.
- 생성 이미지마다 휴대 가능한 완결 시각 브리프를 줍니다. 섹션 역할과 템플릿, 첫째 → 둘째 → 배경의 시선 순서, 색의 역할, 재질과 렌더링, 정확한 글자, 시리즈 공통 조건, 점검 기준을 담고, 구조화된 객체 옆에 바로 붙여넣을 자연어 프롬프트를 함께 전달합니다.

</purpose>

<routing_rule>

결과물이 네이버 블로그 글(또는 그 제목·개요·수정)이고 사용자가 네이버 검색이나 네이버 앱 노출을 신경 쓸 때 `naver-blog-maker`를 씁니다.

다음은 활성하지 않습니다.

- 대상이 구글, 회사 홈페이지, 기술 SEO 점검이면 범위 밖
- 글 없이 네이버 원자료(검색수, 데이터랩 추이)만 원하면 범위 밖
- 네이버 글이 결과물이 아닌데 한국어 글만 다듬어 달라면 범위 밖
- 플랫폼이 티스토리, 워드프레스, 브런치, 뉴스레터면 범위 밖
- 글 묶음, 예약 자동 발행, 댓글·이웃 자동화를 원하면 자동화 부분은 거절(`<forbidden>` 참고)하고 검토용 초안 한 편을 제안

사용자가 이미 쓴 네이버 글은 범위 안입니다. 그 브리프는 작성 경로가 아니라 `rules/repair-method.ko.md`의 수리 경로를 열고, 반대 방향은 없습니다.

이 스킬은 자체 완결형입니다. 글 구조, 네이버 규칙, 문장 단위 자연스러움 규칙(`rules/human-prose.ko.md`)을 모두 직접 갖고 있으며 다른 스킬 설치 여부에 의존하지 않습니다.

</routing_rule>

<instruction_contract>

| 항목 | 계약 |
|---|---|
| 의도 | 시작 질문을 확인한 뒤 네이버 글 한 편, 제목 후보, 인라인 이미지 슬롯과 생성 JSON, 선택한 양식의 본문, 키워드·슬롯·발행 메모를 전달. |
| 범위 | 글 내용과 구조만. 로그인, 발행, 반응 행위, 스크래핑 없음. |
| 권한 | 사용자 요청과 저장소 지침 > `rules/naver-ranking-contract.ko.md`(official 행) > `observed` 기본값 > 사용자가 준 프롬프트 템플릿 > 외부 SEO 가이드. |
| 근거 | 네이버 동작을 말하는 모든 주장은 `references/naver-algorithm-timeline.ko.md`의 `official` 행으로 추적(`references/evidence-digest.ko.md`에 대응표). observed와 folklore는 표시. 정보성 사실은 리서치에서 `URL | 날짜`와 함께 오고, 직접 경험·결과·지불한 가격·브랜드 문장은 사용자에게서만 오며 빈자리는 `[확인 필요]`. |
| 도구 | 주제 리서치용 웹 검색과 페이지 조회. 선택: 실제 검색 결과 확인용 브라우저 도구. 공개 네이버 페이지(데이터랩, 통합검색)는 방문자로 읽음. 그 밖에는 네이버에 닿지 않음. 로그인·스크래핑 없음. |
| 루프 | 초안 → `rules/validation.ko.md` 자체 점검 → 강제 규칙 실패 수정. 수정 최대 두 번, 그 뒤 남은 항목을 밝히고 전달. |
| 출력 | 한국어. 제목 후보 → 선택 양식 본문 → 생성 JSON → 키워드 → 슬롯 → 발행 메모. rich의 제목·태그는 본문과 분리. |
| 검증 | `rules/validation.ko.md`의 초안 점검표. 스킬 변경 시 패키지 점검표(코퍼스 검증기, `bun run --cwd scripts verify`, KO/EN 짝, README 카탈로그). |
| 종료 조건 | 시작 질문 답을 기다린 뒤 작업. 점검표 통과 시 전달. 규제 주제의 필수 출처가 없으면 필요한 자료를 밝히고 중단. 묶음·자동 발행 제외. |

</instruction_contract>

<activation_examples>

긍정:

- "누수 탐지 비용으로 네이버 블로그 글 하나 써줘." (키워드만. 나머지는 리서치가 채움)
- "강남 임플란트 가격 비교 주제로 네이버 블로그 글 써줘, 상위노출 되게."
- "우리 누수탐지 업체 문의 늘리는 네이버 블로그 포스팅 써줘. 브랜드명은 ○○, 가치입증은 이거야."
- "제주 3박4일 여행 후기를 네이버 블로그에 올릴 건데 사람이 쓴 것처럼 써줘."
- "Write a Naver blog post about a 에어프라이어 review that can rank in Naver search."
- "이 네이버 블로그 글 제목이랑 서두만 다시 잡아줘, 낚시 같지 않게."
- "이미 쓴 네이버 블로그 글인데 AI 티가 나. 사람이 쓴 것처럼 다듬어줘. (글 전문 붙여넣음)" (수리 경로 — 앵커 기록, 어미 유지)

부정:

- "우리 회사 홈페이지 SEO 점검해줘." → 범위 밖(웹사이트 SEO)
- "네이버 데이터랩에서 두 키워드 추이만 뽑아줘." → 범위 밖(글 없는 데이터 조회)
- "이 글 번역투만 고쳐줘." (네이버 글 아님) → 범위 밖(문장 다듬기만)
- "티스토리에 올릴 애드센스 글 써줘." → 범위 밖

경계:

- "블로그 글 하나 써줘." — 어느 플랫폼인지 묻고 네이버일 때만 활성.
- "네이버 블로그 글 50개 자동으로 만들어서 올려줘." — 검토용 초안 한 편에는 활성. 묶음과 자동 발행은 거절(R7).
- "협찬 받은 제품인데 광고처럼 안 보이게 써줘." — 활성. 공개 문장은 서두에 유지(R6)하고 아쉬운 점이 있는 실제 후기로 씀.
- "네이버 블로그 글인데 노출은 상관없고 문장만 사람 냄새 나게 다듬어줘." — 수리 경로로 활성. 순위 단계는 건너뛰고 형식 계약과 앵커는 그대로 적용.

</activation_examples>

<workflow>

| 단계 | 작업 | 산출 |
|---|---|---|
| 0. 시작 질문 | 블로그 URL, 정보형·전환형, 선택 업체·제품, 선택 URL·자료, plain·rich를 한 메시지로 확인하고 답을 기다림. 이미 답한 항목은 반복하지 않음. | 확인된 입력 |
| 1. 리서치 | 키워드(또는 브랜드 + 주제 + 가치입증)를 받으면 `rules/topic-research.ko.md` 실행: 검색어 후보, 상위 3편 빈틈 분석, 출처 있는 사실, 경험 슬롯, 인라인 이미지 슬롯. 경험이나 이미지를 받았으면 기록하고 빈틈·이미지 슬롯 단계만 실행. | 사실 묶음 |
| 2. 키워드 | `references/keyword-research.ko.md`대로 검색어 하나와 의도 슬라이스 하나 선택. 공개 도구로 공급·수요 비교. 가능하면 실제 검색 결과 확인. | `검색어 / 슬라이스 / 근거` 한 줄 |
| 3. 구조 | `rules/post-workflow.ko.md` §3 골격 채움: 제목, 커버 이미지 슬롯, 첫 화면(공감 → 답 → 근거 → 범위), 사실이나 슬롯과 인라인 이미지 마커가 각각 있는 근거 섹션 3~6개, 아쉬운 점 섹션, 마무리, [공개, 브랜드 블록, 행동 유도]. | 개요 |
| 4. 초안 | 이 스킬의 형식 계약 아래 `rules/human-prose.ko.md`대로 작성. 제목과 서두는 `references/hook-library.ko.md`에서. 사실은 원문 유지. 이미지 마커는 문장 흐름 안에. `[확인 필요]`는 비워 둠. | 초안 |
| 5. 점검 | `rules/validation.ko.md` 초안 점검표를 실행하며 `references/tell-catalog.ko.md`를 패밀리별로 초안과 대조. 강제 규칙 실패 수정(2회 이하). | 점검된 초안 |
| 6. 전달 | 제목 후보 → plain 텍스트 또는 rich 본문 HTML → 생성 이미지별 JSON → 키워드 → 슬롯 → 발행 메모. | 한국어 결과물 |

</workflow>

받은 초안이 있으면 1~3단계를 대신합니다. 어미와 앵커를 기록한 뒤 `rules/repair-method.ko.md`를 실행합니다. 5~6단계는 그대로이고, 전달에는 텍스트 블록 밖으로 바뀐 점 한두 줄이 더해집니다.

<required>

- 리서치·작성 전에 시작 질문을 한 메시지로 묻고 답을 기다립니다. 답한 항목은 반복하지 않습니다.
- 시작 질문 뒤에는 사실 묶음을 요구하지 않고 키워드로 리서치합니다. 선택 업체 정보가 없어도 슬롯으로 진행합니다.
- 작성자의 주제 레인 안에서 의도 슬라이스 하나에 씁니다. 발행 메모에 맞는 에디터 주제를 적습니다.
- 실제 자료는 `[이미지: 대상 | 캡션]`, 설명 그림은 `[이미지 생성: 대상 | 캡션 | 프롬프트 #n]`을 본문 위치에 둡니다. 생성 JSON은 본문 밖에 번호대로 제공합니다.
- 생성 이미지마다 섹션 역할과 템플릿을 `references/image-prompt-templates.ko.md` §2에서 고르고, 그 객체를 `rules/image-slots.ko.md` §6이 정한 순서로 컴파일합니다. 적용되지 않는 조건부 필드는 아예 없어야 하며 `null`이나 `"N/A"`, 자리표시자로 채우지 않습니다.
- 그려질 글자는 `text[]` 안에서 정확히 한 번 나타나고 `prompt`가 그 모두를 byte 단위로 그대로 담게 씁니다. 진짜 시리즈의 공통 조건은 그 시리즈의 모든 객체에 반복합니다.
- 주제, 정확히 그려질 글자, 편집의 보존·변경 경계가 비어 있으면 그 이미지의 완성 프롬프트를 내지 않습니다. 물어보거나 슬롯을 열어 둡니다.
- plain은 text 펜스 하나, rich는 본문 HTML과 별도 제목·태그로 전달합니다. HTML 소스 복사와 HTML 클립보드 복사를 구분합니다.
- 제목의 약속을 첫 3~5문장에 넣습니다. 모든 섹션에 확인 가능한 상황이나 출처가 있고 최소 한 섹션이 아쉬운 점을 말합니다.
- 목표 검색어는 제목에 한 번, 본문에서는 문장이 필요로 하는 자리에만. 횟수나 밀도 목표 없음.
- 협찬, 자사, 제휴 관계는 첫 단락에서 쉬운 말로 공개합니다.
- 전환형 브랜드 사실은 원문 그대로 넣고 독자의 다음 결정으로 표현한 행동 유도 정확히 하나로 끝냅니다.
