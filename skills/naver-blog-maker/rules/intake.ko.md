# 시작 질문

> 영어 원본: [`intake.md`](intake.md)

**목적**: 리서치나 초안 작성 전에 이 스킬이 보내는 단 한 번의 메시지입니다. 글의 형태를 바꾸면서도 리서치로는 알 수 없는 다섯 가지 사실을 모읍니다. 나머지는 [`topic-research.ko.md`](topic-research.ko.md)가 채웁니다. 한 메시지로 한 번만 묻고, 답한 만큼으로 진행합니다.

## 1. 언제 묻는가

새 글 요청마다 리서치 전에 아직 답하지 않은 항목을 한 메시지로 묻고 답을 기다립니다. 이미 답했거나 생략을 명시한 항목은 반복하지 않습니다. 선택 항목 누락은 막지 않고 아래 기본값을 씁니다.

## 2. 메시지

아래 다섯 항목을 기준으로 아직 답하지 않은 항목만 한국어 목록 하나로 묻습니다.

```
글을 쓰기 전에 다섯 가지만 확인할게요.

1. 네이버 블로그 URL (예: https://blog.naver.com/아이디) — 블로그의 기존 주제 레인과 말투를 맞추려고 봅니다.
2. 글 종류 — 정보형(경험·비교·가이드) / 전환형(업체·제품 문의나 방문이 목표) 중 하나.
3. (선택) 업체명 또는 홍보할 제품 — 아직 정하지 않았다면 비워도 됩니다.
4. (선택) 업체·제품을 볼 수 있는 URL이나 자료 — 홈페이지, 스마트스토어, 카탈로그, 가격표 등.
5. 글 양식 — plain(서식 없는 텍스트) / rich(서식 있는 HTML 본문) 중 하나. rich는 렌더링된 내용을 HTML 클립보드로 복사하며 제목·태그는 따로 입력합니다. 선택하지 않으면 plain으로 진행합니다.
```

## 3. 각 답이 가는 곳

| 항목 | 필수 | 쓰이는 곳 | 없을 때 |
|---|---|---|---|
| 1. 블로그 URL | 예 | 주제 레인 확인(`topic-research.ko.md` §1), 말투 맞추기(방문자로 최근 글 3편 읽기: 어미, 이미지 밀도, 장식 습관) | 레인은 `[확인 필요]`. 어미는 `human-prose.ko.md` §4의 모드 행 기본값 |
| 2. 글 종류 | 예 | `post-workflow.ko.md` §0 | 3번으로 추정. 업체명이 있으면 전환형. 추정했다고 모드 줄에 밝힘 |
| 3. 업체·제품 | 두 유형 모두 선택 | 브랜드 사실 블록, 행동 유도 대상, 공개 문장 | 전환형인데 없으면 브랜드 블록과 행동 유도에 `[확인 필요: 업체명]`을 두고 씀. 정보형은 무시 |
| 4. 업체 URL·자료 | 선택 | 가치입증 사실 원문(방문자로 읽고 숫자는 바꿔 쓰지 않고 인용) | 사용자가 적은 것만 브랜드 사실로 쓰고 나머지 브랜드 주장은 모두 슬롯 |
| 5. 양식 | 예 | `post-workflow.ko.md` §5의 전달 형태와 [`../references/format-options.ko.md`](../references/format-options.ko.md) | plain |

블로그 URL과 업체 URL 읽기는 공개 페이지를 방문자로 읽는 것뿐입니다(로그인 없음, 필요한 페이지 밖 스크래핑 없음). 페이지를 열 수 없으면 발행 전 메모에 적고 계속합니다.

## 4. 답을 받은 뒤

- 답 다섯 개를 한 줄(`블로그 / 모드 / 업체 / 자료 / 양식`)로 답변 맨 위에 되짚고, 더 묻지 않고 `post-workflow.ko.md` §0부터 실행합니다.
- 브리프에 다섯 개가 이미 다 있으면(예: 재방문 사용자가 위 줄을 붙여 넣은 경우) 메시지를 아예 건너뜁니다.
- 키워드, 독자, 길이, 어조, 이미지는 묻지 않습니다. 리서치와 모드 행이 정합니다.
