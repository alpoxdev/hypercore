# 글 작성 워크플로

> 영어 원본: [`post-workflow.md`](post-workflow.md)

**목적**: 네이버 블로그 글 한 편을 브리프에서 사용자가 스마트에디터 ONE에 붙일 초안까지 만드는 순서입니다. 랭킹 규칙은 [`naver-ranking-contract.ko.md`](naver-ranking-contract.ko.md), 훅 패턴은 [`../references/hook-library.ko.md`](../references/hook-library.ko.md)에 있고 문장 규칙은 [`human-prose.ko.md`](../rules/human-prose.ko.md)에 있습니다.

## 0. 모드 결정 (한 절로 밝힘)

| 모드 | 조건 | 필요한 입력 | 결과물 형태 |
|---|---|---|---|
| **정보/경험형** | 홍보할 브랜드·제품·서비스가 없고, 상위에 노출되면서 사람의 경험이나 조사한 설명으로 읽히는 글을 원함 | 최소 키워드나 주제 하나. 있으면 작성자의 경험·사실·이미지 | 제목 후보 + 본문(인라인 이미지 슬롯 포함) + 태그 |
| **전환형** | 브랜드·업체·상품이 지정되고 문의, 방문, 구매를 원함 | 브랜드명, 주제, 가치입증 내용(사실 그대로), 참고내용(비어 있어도 됨), 상업적 관계(자사 / 협찬 / 제휴) | 위와 같음 + 행동 유도 1개 + 공개 문장 |

전환형은 정보/경험형의 모든 규칙을 그대로 따르고 여기에 서두 공개(R6), 브랜드 사실 원문 유지, 글 끝 행동 유도 하나를 더합니다. 판매 목적이라고 근거 기준이 느슨해지지 않습니다.

브리프가 둘을 섞으면(개인 후기인데 매장 링크로 끝남) 전환형입니다.

## 1. 접수 — 사실 묶음

먼저 [`intake.ko.md`](intake.ko.md)의 시작 질문을 확인하고 답을 기다립니다. 그 뒤에는 키워드로 리서치하며 사실 묶음을 추가로 요구하지 않습니다.

- **키워드/주제만, 또는 브랜드 + 주제 + 가치입증인데 경험은 없음**(시드 프롬프트 형태): [`topic-research.ko.md`](topic-research.ko.md)를 전부 실행합니다. 출처 있는 사실, 작성자 본인의 경험만 들어갈 자리의 `[확인 필요]` 슬롯, 인라인 이미지 슬롯이 담긴 아래 사실 묶음을 돌려줍니다. 모드와 양식은 시작 질문에서 확인했습니다.
- **경험, 사실, 이미지를 준 경우**: 그대로 묶음에 기록하고 `topic-research.ko.md`의 빈틈 점검과 이미지 슬롯 단계(§4~§5)만 실행합니다.
- **기존 글을 준 경우**(사용자가 네이버 초안을 붙여넣고 사람이 쓴 것처럼 읽히게 해 달라고 할 때): 받은 글을 바탕으로 두고 어미와 앵커를 기록한 뒤 [`repair-method.ko.md`](repair-method.ko.md)의 수리 경로를 실행합니다. 형식 계약은 그대로 지킵니다. 사용자가 요청하지 않으면 구조를 바꾸지 않고, 받은 글만으로는 설 수 없는 자리에만 `[확인 필요: …]` 슬롯을 넣습니다.

사실 묶음 항목(`topic-research.ko.md` §6): 목표 검색어와 독자 과제, 블로그 주제 레인(모르면 `[확인 필요]`), 상위 3편 갭(공통 / 빠진 것 / 오래된 것), `출처 URL | 날짜 | 섹션`이 붙은 사실, 경험 슬롯, 섹션별 이미지 슬롯, 전환형 브랜드 사실 원문 + 관계, 어미(모르면 경험형 `-했어요`, 전문·서비스형 `-습니다`).

경계: 리서치는 정보 골격을 주지만 작성자가 보고하지 않은 방문, 구매, 결과, 아쉬운 점은 주지 않습니다. 그것은 슬롯입니다. 규제 주제(의료·금융·법률·부동산)인데 묶음에 1차 출처나 날짜 있는 출처가 없으면 여기서 멈추고 필요한 출처 목록을 말합니다.

## 2. 키워드와 의도 점검

목표: 글이 이길 수 있는 검색어 하나와 답할 의도 슬라이스 하나를 고릅니다.

1. 시드를 후보로 확장: 장소, 대상, 모델, 문제, 가격, 계절 수식어. 자동완성과 연관 검색어는 실제 검색 페이지에서만 보입니다. 브라우저 도구가 있으면 모으고 없으면 사용자에게 붙여 달라고 합니다.
2. 공개 도구로 공급과 수요를 따로 측정합니다(절차와 도구 목록은 `../references/keyword-research.ko.md` §3~§4).
   - 공급: 네이버 블로그 검색 결과 페이지나 공개 키워드 도구가 정확한 문구에 대해 보여주는 블로그 문서 수(누적 문서. 월간 발행량이 아님).
   - 수요 형태: 네이버 데이터랩 검색어트렌드로 후보 비교(0~100 상대 지수. 검색량이 아님).
   - 절대 월간 검색량은 네이버 검색광고 키워드도구(로그인)나 외부 도구가 필요합니다. 만들어내지 않습니다.
3. 고른 검색어의 실제 검색 결과를 봅니다(사용자 스크린샷이나 브라우저 도구). 어떤 스마트블록 제목이 뜨는지(인기글, 후기, 비교, 가격…), 쇼핑·플레이스·광고가 블로그를 밀어내는지, 상위 3개 글이 무엇을 약속하는지. 블로그 글이 실제로 나오는 슬라이스에 맞춰 씁니다.
4. 결정을 한 줄로 기록: `검색어 / 의도 슬라이스 / 근거 (문서수·트렌드·SERP)`. "월 200~1,000 검색", "문서수/검색량 ≤ 1" 같은 수치 구간은 단일 출처 경험칙입니다. 선별에는 쓰되 규칙으로 말하지 않습니다.

## 3. 구조 계약

두 모드가 같은 골격을 쓰고 전환형은 대괄호 부분을 더합니다.

```
제목 (20-35자, 검색어 앞쪽, 구체적 보상)
[이미지: 커버 — 무엇을 찍을지 | 캡션]
[공개 문장 — 협찬/자사/제휴일 때, 첫 문단 안]
첫 화면: 구체적 공감 1문장 → 답/결론 → 근거(경험·출처) → 이 글이 다루는 범위
소제목 1..N (독자의 다음 질문 순서; 보통 3-6)
  각 섹션 = 주장 → 확인 가능한 상황/수치/출처 (또는 [확인 필요: …] 슬롯) → [이미지: … | …] 또는 표/목록
  최소 1개 섹션 = 아쉬운 점 / 안 맞는 경우 / 실패한 부분 (없으면 슬롯)
[브랜드 가치입증 — 사용자 입력 그대로, 관련 섹션 안]
마무리: 이제 내릴 수 있는 결정 → 달라지는 조건 → 다음 단계 1개
[CTA 1개 — 독자의 다음 행동으로 표현]
해시태그 3-7개 (정확한 주제·개체)
```

[`image-slots.ko.md`](image-slots.ko.md)대로 실제 자료 `[이미지: 대상 | 캡션]`와 설명 그림 `[이미지 생성: 대상 | 캡션 | 프롬프트 #n]`을 본문에 배치합니다. 생성 마커는 저마다 필요한 섹션 역할과 템플릿을 밝히고, 그 값은 [`../references/image-prompt-templates.ko.md`](../references/image-prompt-templates.ko.md) §2에서 고릅니다. 그래야 초안을 쓰기 전에 골격과 전달될 JSON이 같은 역할을 말합니다. 생성 JSON은 본문 밖에 번호대로 제공합니다. 짧은 문단 사이에 비교·과정·원리 그림을 배치하며 증거 사진을 생성 그림으로 대체하지 않습니다.

경험 슬롯도 본문 안에 `[확인 필요: …]`로 두고 무엇을 쓸지 구체적 예를 붙입니다. 스킬이 채우지 않습니다.

분량 기본값(observed, 비강제): 본문 1,500~3,000자. 의도에 답했으면 멈춥니다. 숫자를 맞추려고 채우지 않습니다.

시드 프롬프트의 7단계는 이렇게 대응합니다. 공감대 → 첫 문장, 소개글 → 첫 화면, 문제점/WHY → 첫 소제목, 반박자료 → 섹션 안의 근거, 주제 정보 → 나머지 섹션, 후킹 → 제목과 첫 화면에만(어휘를 뿌리지 않음), 브랜드 가치입증 → 원문 블록 + 행동 유도.

## 4. 초안 — 내장 문장 규칙 아래에서

문장은 [`human-prose.ko.md`](../rules/human-prose.ko.md) 아래에서 쓰고 이 스킬의 형식 계약을 바깥 제약으로 둡니다. 실제로는:

- `human-prose.ko.md` §4의 장르 행: 경험·후기·일상, 정보·비교·가이드, 전문·서비스 중 하나. 글 전체에 어미 하나.
- 생성 시점에 W-01~W-26을 적용하고, 네이버 특유 S1 추가 항목은 다음과 같습니다. `첫째/둘째/셋째` 뼈대, `결론적으로`, `도움이 되셨다면 공감과 댓글`, `지금 바로`, 만들어낸 퍼센트, 섹션 표시용 이모지, 모든 단락이 같은 길이.
- 장식 예산: [`human-prose.ko.md`](human-prose.ko.md) §4에서 고른 행의 글당 상한(네이버 에디터에서 적용하고 마크다운 `**`는 절대 쓰지 않음).
- 제공받았거나 출처가 있는 사실, 숫자, 가격, 날짜, 브랜드 문장은 그대로 유지합니다. 섹션에 사실 묶음에 없는 사실이 필요하면 `[확인 필요: …]`를 그 자리에 남깁니다. 채우지 않습니다.
- 이미지 마커는 문장 흐름의 일부로 씁니다. 마커는 증명하는 주장 문장 뒤에 오고 다음 문장이 그것을 가리킬 수 있습니다(`위 사진의 온도 차이처럼…`).
- 심화 패스: 5단계 자체 점검에서 [`../references/tell-catalog.ko.md`](../references/tell-catalog.ko.md)를 패밀리별로 훑으며 초안과 대조합니다. `human-prose.ko.md` §3의 패밀리 표 뒤에 있는 개별 패턴을 나쁜 예·좋은 예와 지우는 W-ID로 정리해 둔 파일입니다.

## 5. 자체 점검 후 전달

`human-prose.ko.md` §5의 자체 점검 프로토콜을 먼저 실행한 뒤 [`validation.ko.md`](validation.ko.md)를 실행합니다. 강제 규칙 실패는 전달 전에 고칩니다. 수정은 최대 두 번, 그 뒤에는 남은 것을 보고합니다.

전달 순서:

1. **제목 후보 3개**(결정형 / 질문형 / 경고형 또는 비교형)에 추천 표시.
2. **선택 양식 본문**: plain은 제목·본문·해시태그를 text 펜스 하나에 둡니다. rich는 제목·카테고리·태그와 분리된 본문 HTML이며 [`../references/format-options.ko.md`](../references/format-options.ko.md)를 따릅니다. HTML 소스 복사를 서식 복사라고 말하지 않습니다. 두 양식 모두 마커와 [확인 필요]를 보존합니다.
3. **이미지 생성 JSON**: 생성 마커마다 번호가 같은 JSON 하나. 그 역할의 필드와 바로 붙여넣을 `prompt`를 포함합니다. 없으면 생략. 산문 프롬프트는 이 객체 안에 있으므로 별도 산문 프롬프트 절을 만들지 않습니다.
4. **키워드 결정** 한 줄.
5. **채울 슬롯** — `[확인 필요]` 마커 목록을 순서대로, 각각 무엇을 쓸지 함께.
6. **발행 전 메모**(2~4줄): 모드, 에디터에서 고를 주제, 공개 문장 확인, 링크 확인, 본문이 1,500~3,000자 기본값을 벗어날 때만 분량 메모, 리서치에 쓴 출처 URL(작성자 참고용. 본문에는 넣지 않음).

그 밖에는 없음. 규칙 ID 없음, 등급 표시 없음, 채점표 없음, 피한 tell 언급 없음. 모드 문장과 모든 메모는 텍스트 블록 밖에 두고 블록만 붙여 넣습니다. 사용자가 준 글을 다듬은 수리 실행이면 같은 항목을 전달하고 바뀐 점을 한두 줄 덧붙이며, 이 요약도 블록 밖에 둡니다.

## 6. 금지

- 요청 하나에 글 여러 편, 묶음 변형, 자동 발행용 산출물(R7).
- 경험, 통계, 인용, 자격, 가격을 만들어내는 것, 또는 `[확인 필요]` 슬롯을 그럴듯한 문장으로 채우는 것.
- 시작 질문 뒤 사실 묶음을 필수로 요구하거나 선택 항목 누락 때문에 진행을 막는 것.
- observed 기본값이나 속설을 네이버 규칙으로 말하는 것.
- 시드 프롬프트의 훅 어휘를 그대로 붙이는 것. 훅 라이브러리의 수정된 형태만.
- 체류시간, 댓글, 좋아요, 이웃을 목표로 삼는 것.
- 네이버 로그인, 네이버 API 엔드포인트 호출, 스크래핑.
