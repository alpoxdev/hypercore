# Instagram Card Maker

> 주제나 브랜드 브리프 하나로 조사 근거가 있는 카드뉴스 캐러셀을 만듭니다. 편집 가능한 컴포저, 게시 순서대로 정렬된 같은 크기의 카드 이미지 여러 장, 그것을 받쳐 주는 한국어 캡션을 함께 전달합니다.

<output_language>

사용자 대면 결과물(카드 제목과 본문, 캡션, 대체 텍스트, 출처 원장, 완료 메모)은 모두 한국어로 씁니다. 제품명, URL, 명령어, 파일 경로, 인용한 원문, JSON 키, 코드 식별자는 원형을 유지합니다. 다른 언어는 사용자가 요청할 때만 씁니다. 코드, JSON, 파일 이름은 전달 언어와 무관하게 원형을 유지합니다.

</output_language>

<purpose>

- 주제나 브랜드, 브리프에서 시작합니다. 주제와 독자의 질문을 먼저 리서치한 뒤 구성합니다. 사용자에게 사실 묶음을 먼저 요구하지 않습니다.
- 카드의 모든 주장을 URL과 접근 날짜가 있는 출처로 뒷받침합니다. 직접 경험, 지불한 가격, 결과, 브랜드 문장은 사용자에게서만 오고, 빈자리는 지어내지 않고 명시적 슬롯으로 둡니다.
- 캐러셀을 한 카드에 한 아이디어를 담고 순서가 논증을 쌓도록 구성합니다. 커버만 훅과 제목을 왼쪽 하단에 고정하고 본문은 내용과 이미지 구도에 맞게 배치합니다. 사진과 글자를 분리한 레이어로 합성해 한글을 선명하게 유지합니다.
- 사진이 카드 전체를 채우게 하고, 사진 배경만 살짝 흐리게 합니다. 제목, 본문, 사용자가 준 로고는 선명하게 유지하고, 글자 뒤에 반투명 어둠막을 두어 대비가 사진에 좌우되지 않게 하면서도 사진이 글자 아래에서 보이게 합니다.
- 편집 가능한 JSON 입력, 라이브 갤러리, 카드별 PNG 내보내기, 그리고 사람이 저장 버튼을 누르지 않아도 에이전트가 내보낸 이미지를 읽을 수 있는 기계 판독용 API를 갖춘 HTML 컴포저를 전달합니다.
- 이미지 옆에 사이드카를 함께 전달합니다. 게시글 전체의 단일 `caption.txt`, 카드 수와 순서에 맞는 `alt-text.json`, `sources.md`, `manifest.json`입니다.
- 생성한 사진은 일러스트로 표시하고 출처를 남깁니다. 생성 이미지를 실제 매장, 제품, 영수증, 증명서, 결과로 제시하지 않습니다.

</purpose>

<routing_rule>

결과물이 인스타그램 캐러셀이나 카드뉴스 세트(같은 크기 이미지 여러 장과 캡션)이고 사용자가 읽히는 한국어 결과와 재현 가능한 컴포저를 신경 쓸 때 `instagram-card-maker`를 씁니다.

다음은 활성하지 않습니다.

- 플랫폼이 인스타그램이 아니고 사용자가 다른 채널을 지목하면 범위 밖
- 이미지 한 장을 편집·보정·변환하려 하면 범위 밖
- 카드 세트가 결과물이 아닌데 글만 다듬거나 블로그 글을 쓰려 하면 범위 밖
- 게시·예약·API 업로드를 원하면 자동화 부분은 거절(`<forbidden>` 참고)하고 수동 게시용 이미지와 캡션을 전달

이 스킬은 자체 완결형입니다. 카드 계약, 컴포저 자산, 캡션·대체 텍스트 규칙, 검증 루프를 모두 직접 갖고 있습니다. 다른 스킬 설치에 의존하지 않으며 다른 스킬을 지목하지도 않습니다.

</routing_rule>

<instruction_contract>

| 항목 | 계약 |
|---|---|
| 의도 | 시작 질문을 확인한 뒤 `.hyper/instagram-card-maker/<slug>/`에 내장 문서가 든 HTML 컴포저, 순서대로 정렬된 카드 PNG 이미지, `caption.txt`, `alt-text.json`, `sources.md`, `manifest.json`을 전달. |
| 범위 | 카드 내용, 카드 레이아웃, 캡션, 대체 텍스트, 컴포저 자산. 로그인, 게시, 예약, API 업로드, 다른 플랫폼 없음. |
| 권한 | 사용자 요청과 저장소 지침 > 리서치한 출처 원장 > 이 패키지의 기본값(4:5, 커버 왼쪽 하단, 내용에 맞는 본문 배치, 사진 배경만 블러, WAI 대비 기준) > 외부 크기 가이드. |
| 근거 | 사실을 말하는 모든 카드 주장은 `sources.md`의 `URL | 접근 날짜` 출처로 추적. 직접 경험, 지불한 가격, 결과, 브랜드 문장은 사용자에게서만 오고 빈자리는 슬롯. 생성 사진은 `manifest.json`에 `generated`로 표시하고 일러스트로 명시. |
| 도구 | 주제 리서치용 웹 검색과 페이지 조회. 컴포저 실행·내보내기용 Canvas·File API가 있는 브라우저. 존재하지 않는 사진이 필요하고 환경이 노출하며 사용자가 원할 때만 네이티브 이미지 생성. 그 밖에는 인스타그램에 닿지 않음. 로그인·스크래핑 없음. |
| 루프 | 구성 → 컴포저 자체 검증과 `validation` 점검표 → 강제 실패 수정. 수정 최대 두 번, 그 뒤 남은 항목을 밝히고 전달. 검증 오류가 남아 있으면 컴포저가 내보내기를 거부. |
| 출력 | 한국어. 카드 제목·본문, 캡션, 대체 텍스트, 출처 원장, 완료 메모. 기계 판독용: `manifest.json`, `alt-text.json`, `window.cardStudio` API 결과. |
| 검증 | 컴포저의 내보내기 계약(`window.cardStudio.exportCards()`)과 `validation` 점검표. 패키지 변경 시 코퍼스 검증기, `--require-self-containment`를 붙인 저작 검증기, `bun run --cwd scripts verify`. |
| 종료 조건 | 시작 질문은 한 번만 묻고 다시 묻지 않음. 점검표 통과 시 전달. 필수 사실의 근거를 찾지 못하면 필요한 출처를 밝히고 중단. 게시·예약은 하지 않음. |

</instruction_contract>

- "브랜드 로고 넣고 카드뉴스 5장 + 한국어 캡션 뽑아줘. 사진은 생성해도 돼."
- "Build an Instagram carousel card set (1080x1350) for a skin-care brand, with a Korean caption."
- "이 원고를 카드뉴스로 쪼개서 이미지까지 내보내줘."

부정:

- "인스타그램에 자동으로 예약 발행해줘." → 범위 밖(자동화. 수동 게시용 이미지와 캡션을 전달)
- "이 사진 한 장 보정해줘." → 범위 밖(단일 이미지 편집)
- "이 글 번역투만 고쳐줘." → 범위 밖(산문 다듬기, 카드 세트 없음)
- "유튜브 썸네일 만들어줘." → 범위 밖(다른 플랫폼)

경계:

- "카드뉴스 만들어줘." — 어느 플랫폼인지, 어떤 형식인지 묻고 인스타그램일 때만 활성.
- "카드뉴스 30장 만들어줘." — 활성. 앱 캐러셀은 최대 20개이므로 그 안에서 계획하고 그 사실을 말함.
- "로고는 내가 준 파일 그대로 써줘." — 활성. 준 로고는 그대로 배치하고 다시 그리거나 바꾸지 않음.
- "사진은 생성해도 되는데 실제 매장 사진처럼 보이게 해줘." — 활성. 생성 사진은 일러스트로 표시하고 실제 매장으로 제시하지 않음.

</activation_examples>

<trigger_conditions>

요청이 인스타그램 캐러셀, 카드뉴스 세트, 또는 캡션과 함께 여러 장짜리 이미지 시리즈를 지목하고 결과물이 사용자가 게시할 이미지일 때 활성합니다. 사용자가 주제나 브랜드, 원고를 주고 카드 이미지와 캡션을 요청할 때도 활성합니다.

인스타그램이 아닌 플랫폼, 단일 이미지 편집, 산문만 있는 요청, 게시·예약·업로드 요청에는 활성하지 않고 `routing_rule`대로 처리합니다.

</trigger_conditions>

</loop_policy>

| 6. 점검 | `validation` 점검표와 컴포저 검증을 돌리고 강제 실패를 고칩니다(≤ 2회). | 점검된 세트 |
| 7. 전달 | `.hyper/instagram-card-maker/<slug>/`에 `index.html`, `cards/NN.png`, `caption.txt`, `alt-text.json`, `sources.md`, `manifest.json`을 씁니다. | 한국어 결과물 |

- 게시글 전체의 단일 `caption.txt`를 쓰고 `alt-text.json`을 카드 수·순서와 맞춥니다.

- 모든 이미지와 폰트 데이터를 `index.html` 안에 data URI로 내장합니다. 원격 스크립트와 네트워크 의존성을 넣지 않습니다.
- 수정 한도 뒤에도 필요한 사진, 사실, 내보내기가 빠져 있으면 미완성 초안과 정확한 원인을 보고합니다. 게시 준비가 끝난 세트라고 표시하지 않습니다.
