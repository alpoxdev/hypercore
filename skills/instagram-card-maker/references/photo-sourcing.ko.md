# 사진 확보

> 영어 정본: [`photo-sourcing.md`](photo-sourcing.md)

사진을 확보하는 동안 읽습니다. 이 파일은 사진 출처, 생성 사진 표시, 로고 처리를 다룹니다.

## 1. 출처

카드마다 사진에 `photoSource` 문자열과 `generated` 플래그가 있습니다. 둘 다 `manifest.json`과 `sources.md`에 기록합니다.

- 제공된 사진: 어디서 왔는지와 허가나 라이선스를 `photoSource`에 적습니다.
- 생성 사진: `generated: true`이며 같은 플래그가 `manifest.json`에 드러납니다.
- 출처나 허가를 모르는 사진은 카드가 아니라 슬롯입니다.

## 2. 생성 사진

생성 사진은 일러스트입니다.

- `photoSource`와 그것이 나오는 캡션에 생성임을 표시합니다.
- 실제 매장, 제품, 장소, 영수증, 증명서, 계기 판독, 결과, 전후 사진으로 제시하지 않습니다.
- 생성 이미지를 실제 사건의 증거로 쓰지 않습니다.

## 3. 로고

제공된 로고는 준 그대로 배치합니다.

- 다시 그리거나 색을 바꾸거나 잘라 넣거나 늘리거나 스타일을 바꾸지 않습니다.
- `logo` data URI로 전달하고 컴포저가 원래 가로세로 비율로 그립니다.
- 흐리게 하지 않습니다. 사진 배경만 흐려집니다.

## 4. data URI 규칙

컴포저는 사진, 로고, 폰트 데이터를 해당 형식의 `data:` URI로만 받습니다. 바이트를 내장하고 원격 URL을 넘기지 않습니다. 그래야 `index.html`이 네트워크 의존성 없이 자체 완결됩니다.

## 5. 사진이 없을 때

카드에 사진이 필요하고 이미지 생성 기능이 있으면 구체적인 장면을 정해 실제로 생성합니다. 프롬프트만 전달하고 끝내지 않습니다. 같은 시리즈의 조명, 색, 주제는 유지하되 각 카드의 역할에 맞게 장면을 바꿉니다. 배경에는 글자와 로고를 넣지 않도록 요청하고 정확한 한글과 제공된 로고는 나중에 합성합니다. 생성 파일을 모두 직접 확인하고 출처를 기록한 뒤 실제 바이트를 `photo` data URI로 바꿉니다.

카드에 필요한 사진이 없고 환경이 이미지 도구를 노출하지 않으면 사진을 슬롯으로 두고 그렇게 말합니다. 그라디언트만 있는 자리표시자를 사진인 것처럼 전달하지 않고, 생성하지 않았는데 사진을 생성했다고 주장하지 않습니다.
