# Batch Selection

선택 조건이나 배치가 나오면 이 규칙을 사용한다. 고정 목록, 질의, 중복 제거, 레인 묶기, 명세 쓰기를 소유한다.

## 1. 목록 고정

1. 사용자의 말을 완전한 질의 하나로 바꾼다. 사용자가 준 모든 조건을 유지하고, 저장소 범위와 열린 상태 필터만 더한다.
2. 결과를 완전히 모은다. 모든 페이지, 풀 리퀘스트 제외, 반환 행 수와 총계 대조.
3. 상한에 걸렸거나 일부만 왔거나 실패했으면 멈춘다. 한계를 보고하고, 질의를 조용히 좁히거나 첫 페이지만 취하지 않는다.
4. 저장소와 이슈 번호로 중복을 제거하고, 첫 등장 순서를 정규 순서로 유지한다.
5. 이 시점에 목록이 고정된다. 나중 발견은 다음 배치의 새 후보로 보고하고 여기에 추가하지 않는다.

완전한 결과가 비어 있으면 레인 없이 끝나고, 한 줄 메모 외에는 명세를 만들지 않는다.

## 2. 그래프 재도출

`hyper:` 블록이 입력이고 간선은 계산하지, 그대로 믿지 않는다.

1. 이슈마다 `hyper:` 블록을 읽는다. 블록이 없는 이슈는 공백이다. `## Scope`에서 쓰기 집합을 다시 도출하고 명세 행에 `block: missing`을 표시한다.
2. `touches` 겹침 간선을 만든다. 두 이슈의 `touches`가 같은 경로를 공유하거나 한 글롭이 다른 쪽 경로를 덮을 때다.
3. 선언된 `depends_on`과 `conflicts_with` 간선과 합친다.
4. 이슈 사이의 순환은 차단 요인이다. 이슈 번호와 함께 보고하고 그 성분만 멈춘다. 순서를 만들어 내지 않는다.

## 3. 레인 묶기

레인은 정해진 순서로 처리하는 쓰기 집합 하나다. 레인은 병렬로 돌고, 레인 안의 이슈는 순서대로 돈다.

1. 겹침 그래프의 연결 성분이 레인이 된다. 간선이 없는 이슈는 자기 레인이다.
2. 레인마다 위상 정렬한다. 사이에 경로가 없는 두 이슈는 선언 순서, 낮은 이슈 번호 우선으로 둔다.
3. 레인 수는 로컬 동시 실행 한도, 기본값 4에서 자른다. 초과 레인은 대기하고 그 이슈는 레인 순서를 유지한다.
4. `lane_hint`가 유일하면 레인 이름으로 쓰고, 아니면 `<가장 낮은 이슈 번호>-<짧은 슬러그>`를 쓴다.

레인 수를 줄이려고 두 레인을 합치지 않는다. 같은 경로를 쓰는 두 이슈를 서로 다른 레인에 두지 않는다.

## 4. 명세

`references/batch-manifest.md` 형식으로 `.hyper/issues/<slug>/batch.md`를 쓴다. 담는 내용은 다음과 같다.

- 정확한 질의와 수집 완전성 증거
- 번호, 제목, 분류, 레인, 크기, 검증 명령이 붙은 정규 고정 목록
- 레인별 순서와 쓰는 경로의 합집합을 담은 레인 표
- 차단 요인: `hyper:` 블록 누락, 순환, 분할이 필요한 이슈
- 다음 단계가 읽는 핸드오프 줄

## 5. 배치가 하지 않는 일

- 구현, 브랜치 생성, 커밋, 푸시를 하지 않는다.
- 닫힌 이슈를 다시 열거나 기존 브랜치를 자기 것으로 가져오지 않는다.
- 구현이 쉬워졌다는 이유로 고정 목록에 이슈를 추가하지 않는다.
- 막혀 보인다는 이유로 이슈를 빼지 않는다. 차단 요인을 기록한다.
