# 레이아웃과 활자

슬라이드가 빽빽할 때, 활자가 이상해 보일 때, 방 뒤에서도 읽혀야 할 때 이 규칙 파일을 사용합니다. 좌표는 `assets/runtime/layout.jq`에 있고, 이 파일은 작성자가 그 안에서 해야 할 판단을 설명합니다.

## 1. 격자

| 값 | EMU | 인치 |
|---|---|---|
| 슬라이드 | 12192000 × 6858000 | 13.333 × 7.5 |
| 여백 | 609600 | 0.667 |
| 본문 폭 | 10972800 | 12.0 |
| 제목 영역 | y 533400, 높이 838200 | 0.583, 0.917 |
| 본문 시작 | y 1600200 | 1.75 |
| 본문 끝 | y 6248400 | 6.833 |
| 바닥글 | y 6355080 | 6.95 |

왼쪽 끝은 카드와 표까지 모두 같은 여백을 씁니다. 이미지 슬라이드를 뺀 나머지는 가로 가운데 정렬을 하지 않습니다. 제목 왼쪽 끝과 맞지 않는 가운데 열은 실수로 읽힙니다.

## 2. 활자 크기

| 역할 | 포인트 | 이유 |
|---|---|---|
| 표지 제목 | 44 | 덱에서 유일하게 40포인트를 넘는 요소 |
| 장 번호 | 15, 강조색 | 제목이 아니라 이름표 |
| 장 제목 | 36 | |
| 슬라이드 제목 | 30 | 한 줄, 한국어 약 20자 |
| 도입 문장 | 17 | 제목 아래 한 문장 |
| 본문 | 18~22, 블록에 맞춰 키움 | 방에서 읽히는 크기, 30포인트 제목 아래로 제한 |
| 하위 항목 | 16 | 본문에서 2포인트 뺀 값 |
| 카드 제목 | 17, 강조색 | |
| 카드 항목 | 15 | |
| 숫자 값 | 46 | |
| 숫자 이름표 | 15 | |
| 숫자 설명 | 12, 보조색 | |
| 표 | 13 | |
| 캡션 | 12, 보조색 | |
| 인용 | 32 | |
| 바닥글과 쪽 번호 | 11, 보조색 | |

규칙이 둘 따라옵니다. 본문은 15포인트보다 작게 쓰지 않습니다. 그 아래로 내려가면 프로젝터에서 글자가 결이 됩니다. 강조는 크기가 아니라 굵기와 색으로 만듭니다. 30포인트 제목과 18포인트 본문이면 충분히 갈리므로, 24포인트짜리 "중요" 항목은 일관성만 깨뜨립니다.

글머리 슬라이드는 본문 영역에 맞춰 글자를 키우되 넘기지 않습니다. 18, 19, 20, 21, 22포인트를 차례로 시도해 영역에 들어가는 가장 큰 크기를 씁니다. 상한은 22포인트(`T_BODY_MAX`)라서, 항목이 네 개인 슬라이드에서도 본문이 제목의 3분의 2를 넘지 않습니다. 그래도 자리가 남으면 남은 높이를 문단 사이 여백으로 나눠 넣습니다. 문단당 최대 18포인트이며, 페이지 아래에 빈 띠 하나로 남기지 않습니다.

## 3. 여백

- `spaceBefore`는 포인트이고 기본값 6은 문단 사이 여백입니다. 줄 간격은 아닙니다. 줄 간격은 읽는 사람과 글꼴에 맡깁니다.
- 카드와 숫자는 304800 EMU(0.333인치) 간격을 씁니다. 더 벌리면 한 줄이 따로 노는 물건으로 갈라지고, 좁히면 하나로 뭉칩니다.
- 도입 문장은 본문을 640080 EMU 아래로 밉니다. 첫 항목에 여백을 더 얹지 않습니다. 배치가 이미 상자를 옮겼습니다.
- 세로 가운데 정렬은 한 줄짜리 상자에만 씁니다. 여러 줄 상자를 가운데로 고정하면 글자를 고칠 때 위치가 움직여, 같은 슬라이드의 두 판이 달라 보입니다.
- 카드 높이는 가장 긴 열이 필요로 하는 만큼만 씁니다. 제목 띠, 줄바꿈된 항목, 아래 여백을 더해 정합니다. 본문 높이의 일정 비율로 고정하면 짧은 항목 셋 아래에 빈 판이 크게 남고, 본문을 넘겨 자라면 잘리지 않고 `LAYOUT_OVERFLOW`로 보고됩니다.

## 4. 색

- 덱마다 강조색 하나를 씁니다. 슬라이드마다 눈이 먼저 닿아야 할 한 곳을 표시합니다. 숫자 값, 카드 제목, 표 머리, 차트 첫 계열입니다.
- 보조색은 받쳐 주는 글자에 씁니다. 캡션, 노트, 바닥글, 하위 항목입니다. 주장에는 쓰지 않습니다.
- 어두운 슬라이드(표지, 장, 인용)는 팔레트의 어두운 토큰을 씁니다. 밝은 본문색을 어두운 배경에 얹으면 상태 나쁜 프로젝터에서 글자가 사라집니다.
- 대비는 본문이 4.5:1 이상, 큰 글씨가 3:1 이상입니다. `ink`와 `mono` 팔레트는 이 기준을 넘습니다. 직접 지정한 `accent`는 글자색으로 쓰기 전에 확인해야 합니다.

## 5. 표와 차트

- 표는 머리 행을 강조색으로 채우고 본문 행을 표면색으로 번갈아 칠합니다. 열은 여섯 개까지입니다. 열 폭이 같으므로 긴 문장이 들어간 열은 줄바꿈되고 행 높이를 밀어냅니다.
- 행 높이는 본문 영역을 행 수로 나눈 값이며 0.35~0.8인치로 자릅니다. 0.35 하한이 이기기 시작하는 것은 머리를 포함해 15행(캡션이 있으면 14행)이고, 그때부터 표가 본문 아래로 넘치며 렌더러가 넘침으로 보고합니다. 그 전에 표를 나눕니다.
- 차트는 첫 계열이 강조색을 갖고 나머지는 보조색, 선색, 표면색으로 밀립니다. 조각이 다섯을 넘는 원형 차트는 읽히지 않습니다. 막대 차트로 바꿉니다.
- 차트 값은 숫자여야 합니다. 문자열로 넣으면 범주 이름으로 그려지고 조용히 평평한 차트가 됩니다.
- 한 장에 단위가 둘이면 `combo`를 씁니다. 막대는 왼쪽 축을, 선은 눈금선이 없는 오른쪽 보조 축을 읽습니다. 비율과 부피를 한 축에 놓으면 비율이 기준선에 납작해져 0으로 읽힙니다.
- 가로 차트는 범주 이름이 길 때 씁니다. 세로 차트는 이름표를 돌려 세웁니다. 누적 차트는 합계에 의미가 있을 때만 구성을 보여 줍니다.
- 산점도의 범주는 숫자로 읽히면 x가 됩니다. 값을 두 축에 함께 쓰지 않습니다. 원점을 지나는 대각선이 그려집니다.

## 6. 이미지

- `fit`이 무엇을 잃을지 정합니다. `contain`은 그림 전체를 지키고 상자에 여백을 남기므로 스크린샷처럼 그림이 증거일 때 맞습니다. `fill`은 상자를 지키고 가운데를 `srcRect`로 잘라 내므로 질감과 `hero`에 맞습니다.
- `aspect`는 파일 크기를 읽을 수 없을 때만 적습니다. 배치는 파일 헤더에서 픽셀 크기를 먼저 읽으므로, 값이 틀리면 엉뚱한 띠를 자르거나 맞는 크롭에 여백을 붙입니다.
- 모든 그림은 `alt`를 가집니다. `descr`로 적히고 화면 읽기 프로그램이 읽으며 그림이 로드되지 않을 때 보입니다. 없으면 `IMAGE_NO_ALT`로 보고합니다.
- 캡션은 그림 높이 위에서 자기 자리를 먼저 비우므로 설명하는 사진을 덮을 수 없습니다.
- `gallery`는 사진 1~4장을 받고 각 사진 아래에 설명을 답니다. 글 단락 옆에 사진 둘은 배치 문제이지 사진 문제가 아닙니다. 하나면 `imagetext`, 여러 장이면 `gallery`를 씁니다.
- 글자 아래 사진에는 고정 덮개를 깝니다. 기본 `0.55`이고 복잡한 사진은 올리고 어두운 사진은 내립니다. 그라디언트 덮개는 자기 빛이 있는 사진 위에서 보이지 않고 값을 읽어 확인할 수도 없습니다.

## 7. 전달 전에 확인할 것

- 제목이 한 줄인지. 줄바꿈됐으면 활자를 줄이지 말고 제목을 줄입니다.
- 본문 폭을 넘는 항목이 없는지, 잘려서 말줄임이 붙은 항목이 없는지.
- 캡션이 가리키는 대상 바로 아래에 있는지. 다음 대상 아래에 있지 않은지.
- 표지 슬라이드를 뺀 모든 슬라이드에 바닥글이 있고 쪽 번호가 맞는지.
