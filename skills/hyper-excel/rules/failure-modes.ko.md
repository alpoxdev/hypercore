# 실패 유형

> 하나하나가 "끝난 것처럼 보이는데 틀린" 스프레드시트를 만든다. 각각에 도구가 보고하는 탐지가 있다.

## 1. 숫자가 텍스트로 저장됨

증상: 열에 `SUM`을 걸면 0이 나오거나 행을 건너뛴다. 엑셀에서 셀에 작은 초록 삼각형이 뜬다.

원인: CSV 가져오기, 웹 페이지에서 복사-붙여넣기, 앞에 붙은 아포스트로피 때문에 값이 문자열로 남는다.

탐지: `profile`이 텍스트와 숫자가 섞인 열에 `MIXED_TYPES`를, 앞자리 0이 사라질 값에 `LEADING_ZERO`를 보고한다. `verify_formulas`는 산술 연산이 텍스트 셀에 닿으면 `TEXT_NUMBER`를 올린다.

고침: 의도한 타입을 확인한 뒤 `--set-value`로 변환하거나, 빌드 시점에 숫자로 내보낸다. 수식을 `VALUE()`로 감싸 "고치는" 것은 금지다. 원본 데이터가 여전히 틀렸다.

## 2. 짧은 합계 범위

증상: 합계가 조금 모자란다. 표에는 모든 행이 들어 있다.

원인: 마지막 행을 붙이기 전에 수식을 썼거나, 필터로 행을 숨긴 뒤 보이는 부분에만 소계를 걸었다.

탐지: `verify_formulas`는 합계 범위가 이어진 데이터보다 먼저 끝나거나, 데이터 블록 안의 빈 행에서 멈추거나, 합계가 자신이 합하는 범위 안에 있으면 `RANGE_GAP`를 보고한다.

고침: 범위를 늘리거나 표 열을 참조한다. 새 합계를 독립 계산과 대조한다.

## 3. 낡은 캐시

증상: 다른 프로그램(pandas, `data_only=True` 스크립트)은 옛 숫자나 빈 값을 보여준다. 엑셀은 맞는 값을 보여준다.

원인: 수식을 `<v>` 없이 쓴 도구로 파일을 만들었거나, 데이터가 바뀌기 전에 캐시를 계산했다.

탐지: `inspect`가 `W_FORMULA_NO_CACHE`를 올리고 시트별 `formulaWithoutCache`를 보고한다. `verify`는 `totals.uncached`를 `mismatches`와 따로 센다.

고침: `recalc`로 값을 저장하거나, 캐시를 그대로 두고 어떤 리더가 빈 값을 볼지 알린다. 캐시와 재계산 개수는 따로 보고한다. 하나의 "불일치" 숫자로 합치지 않는다.

## 4. 퍼센트 100배 오류

증상: 성장률이 15%가 아니라 1,500%로 보인다.

원인: 값을 퍼센트 서식으로 `15`로 저장했거나, 일반 서식으로 `0.15`를 넣었다. 맞는 것은 `0.15`에 `0.0%`뿐이다.

탐지: `verify_formulas`는 퍼센트 서식 셀이 1보다 큰 값을 담으면 `PERCENT_AS_WHOLE`을, `profile`은 가져온 텍스트 안의 `%` 접미사에 `PERCENT_AS_TEXT`를 보고한다.

고침: 100으로 나눠 저장하고 퍼센트 서식을 적용한다. 숫자 값은 분수로 유지한다.

## 5. 날짜 로캘 반전

증상: `03/04/2026`이 한 도구에서는 3월 4일, 다른 도구에서는 4월 3일이 된다.

원인: 일-월 순서 로캘에서 입력·파싱했거나, 문자열로 저장했거나, 모호한 형식으로 변환했다.

탐지: `profile`은 한 열에 날짜 패턴이 섞이거나 ISO 날짜와 로캘 날짜가 같이 있으면 `AMBIGUOUS_DATE`를, 모든 값이 같은 비 ISO 패턴이면 `LOCALE_DATE_TEXT`를 보고한다.

고침: 날짜를 직렬 숫자로 저장하고 `yyyy-mm-dd` 서식을 명시한다. 날짜를 텍스트로 저장하지 않고, 일-월과 월-일 사이를 추측하지 않는다. 모호하면 모호하다고 보고한다.

## 6. 앞자리 0 소실

증상: 우편번호나 상품 코드 `00123`이 `123`이 된다.

원인: 가져오기나 변환에서 열을 숫자로 판정했다.

탐지: `profile`이 `LEADING_ZERO`를 개수와 열 이름으로 보고하고, 열 레코드에 `leadingZeros` 개수를 담는다.

고침: 텍스트 서식(`@`)으로 저장하고 빌드 스펙에서 열을 텍스트로 표시한다.

## 7. 자기 참조와 순환

증상: 엑셀이 순환 참조 경고를 띄운다. 값은 0이거나 마지막에 입력한 값이다.

원인: 합계를 자기 범위 안에 두었거나 수식 사슬이 순환한다.

탐지: `verify_formulas`는 직접 걸리면 `SELF_REFERENCE`를, 더 긴 고리는 순환으로 보고하고 고리의 모든 셀을 밝힌다.

고침: 합계를 범위 밖으로 옮기거나 고리를 끊는다. 반복 계산을 켜서 덮지 않는다.

## 8. 가져온 텍스트의 수식 주입

증상: 누군가 파일을 열기 전까지는 없다. `=`, `+`, `-`, `@`로 시작하는 값이 수식이나 DDE 호출로 실행된다.

원인: 가져온 CSV 텍스트를 작성기가 선행 `=`를 이스케이프하지 않고 수식으로 썼다.

탐지: 빌더가 선행 `=`, `+`, `-`, `@`를 텍스트 셀로 이스케이프하고 개수를 보고한다. 그 보고를 검토한다.

고침: 텍스트(문자열 타입)로 저장하고, 어느 열에서 몇 개를 중화했는지 보고한다. 값을 조용히 지우지 않는다. 사용자가 봐야 할 값일 수 있다.

## 9. 수식이 많은 파일에 캐시 없음

증상: 계산하지 않는 리더로 받은 사람이 빈 보고서를 본다.

원인: 수식을 캐시 없이 썼고 재계산하지 않았다.

탐지: `inspect`가 `W_FORMULA_NO_CACHE`를 시트별 `formulaWithoutCache` 개수와 함께 올린다. `verify`는 값이 없는 수식이 하나라도 있으면 `cache_complete`를 `partial`로 보고한다.

고침: `recalc`. 값을 쓰고 `fullCalcOnLoad`를 설정하므로 엑셀은 열 때 원본부터 다시 계산한다.

## 10. 대상 엑셀이 모르는 최신 함수

증상: 구버전 엑셀에서 `#NAME?`. `XLOOKUP`, `LET`, `FILTER`, `TEXTJOIN`으로 쓴 파일이다.

탐지: `verify_formulas`가 함수와 셀을 담아 `NEWER_FUNCTION`을 보고한다.

고침: 동등한 식으로 바꾸거나, 파일이 요구하는 최소 엑셀 버전을 밝힌다.

## 11. 큰 시트의 휘발성 수식

증상: 파일을 여는 데 오래 걸리고, 키를 누를 때마다 전부 다시 계산한다.

탐지: `verify_formulas`가 함수별 셀 개수와 함께 `VOLATILE_FUNCTION`을 보고한다.

고침: `OFFSET`/`INDIRECT`/`TODAY`/`NOW`/`RAND`를 정적 참조나 보조 열로 바꾸거나, 왜 필요한지 밝힌다.

## 12. 들쭉날쭉한 행과 한 열의 혼합 타입

증상: 합계는 되는데 필터나 피벗에서 행이 조용히 빠진다.

원인: 한 열에 숫자와 텍스트가 섞였거나, 데이터 블록 안에 빈 행이 있다.

탐지: `profile`이 열별 `kind`를, 혼합 열에 `MIXED_TYPES`를 보고하고 열 레코드가 빈 칸을 센다.

고침: 빌드 전에 정규화하고, 빠지거나 강제 변환된 행을 보고한다.
