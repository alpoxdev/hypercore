# 스토리보드 메이커

> English version: [`SKILL.md`](SKILL.md)

> 대본이나 줄거리 하나로 숫자에서 그린 패널, 연속성 검사, A4 가로 인쇄가 되는 자체 완결 HTML 영화 스토리보드를 만듭니다.

<output_language>

사용자 대면 문자열은 모두 한국어로 씁니다. 씬 헤딩, 액션, `intent`, 샷 리스트, 패널 메모, 완료 메시지가 여기에 해당합니다. 대사는 사용자가 번역을 요청하지 않는 한 원천이 준 언어를 유지합니다. JSON 키, 열거값, 파일 이름, 오류·경고 코드는 원형을 유지하고, 패널에 인쇄되는 앵글 이름에는 항상 숫자와 한국어 용어를 함께 붙입니다.

</output_language>

<purpose>

- 원천에서 시작합니다. 카메라를 고르기 전에 대본을 읽고 비트로 나눕니다. 이 스킬은 대본 파서를 포함하지 않으므로 읽는 일은 에이전트가 합니다.
- 패널마다 카메라 높이, 피치, 방위, 롤, 렌즈 다섯 숫자와 샷 크기로 그립니다. 로우 앵글, 클로즈업 같은 이름은 그 숫자에서 인쇄되는 라벨이며 입력이 아닙니다.
- 썸네일에서도 읽히는 선화를 그립니다. 막대 선 대신 상자를 쓰고, 얼굴 표식은 카메라를 향한 반구에만 그리며, 뒤통수에는 어느 각도에서나 머리카락 덩어리를 두고, 몸통 뒤의 팔다리가 비쳐 보이지 않게 은선 제거를 합니다.
- 패널 그림은 `image-maker` 스킬에 정확한 컴파일 프롬프트와 참고 이미지 없음을 넘겨 만들고, 돌아온 그림을 넣기 전에 검사합니다. image-maker가 없거나 그림을 돌려주지 않으면 선화를 두고 다음 실행을 위해 프롬프트를 저장합니다.
- 카메라 줄에 숫자와 한국어 용어를 정해진 순서로 인쇄해, 페이지를 보고 바로 촬영할 수 있게 합니다. "로우"가 무엇을 뜻했는지 되묻지 않아도 됩니다.
- 전달 전에 연속성을 검사합니다. 180도 축, 30도 규칙, 시선 일치, 화면 방향, 점프컷, 과부하된 무브를 봅니다. 기하를 고치거나, 방법과 이유를 붙여 위반을 기록합니다.
- 네트워크 없이 디스크에서 열리는 폴더 하나를 전달합니다. `index.html`, `storyboard.json`, `shot-list.md`, `manifest.json`이고, A4 가로 인쇄와 씬별 평면도가 들어 있습니다.
- 렌더러는 의존성 없이 유지합니다. 라이브러리, CDN, 웹 폰트, 원격 요청, 문서 밖의 이미지 파일이 없습니다.

</purpose>

<routing_rule>

결과물이 영화 스토리보드, 즉 대본·줄거리·장면 목록에 대한 선화 패널과 카메라 값, 이동 표기, 연속성 검사일 때 `storyboard-maker`를 씁니다.

다음은 활성하지 않습니다.

- 결과물이 움직이는 것이면(애니매틱, 영상, GIF, 프레임 연속) 범위 밖입니다. 이 스킬은 정지 패널만 만듭니다.
- 선화 대신 사진이나 실존 인물의 얼굴을 패널에 원하면 범위 밖입니다. 패널 그림은 이 대본의 연출과 인물에서 나옵니다.
- UI 와이어프레임, 만화 페이지, 발표 슬라이드를 원하면 범위 밖입니다. 결과물 모양이 카메라 줄이 붙은 영화 패널이 아닙니다.
- 기존 영화의 프레임이나 콘티를 복제·트레이스하려 하면 그 부분은 거절하고(`<forbidden>` 참고), 이 대본의 블로킹으로 보드를 만듭니다.
- 다른 대본 형식의 파서를 원하면 범위 밖입니다. 에이전트가 대본을 읽고 문서를 씁니다.

이 스킬은 패널 그림을 뺀 나머지가 자체 완결형입니다. 입력 스키마, 렌더러 자산, 연속성 규칙, 검증 루프, 선화 유지 결정을 직접 갖고 있습니다. 패널 그림 생성은 `image-maker` 스킬에 위임하며 선택 사항입니다. 없어도 보드는 완성되고, 다른 스킬은 지목하지 않습니다.

</routing_rule>

<instruction_contract>

| 항목 | 계약 |
|---|---|
| 의도 | 시작 질문을 한 번 확인한 뒤 `.hyper/storyboard-maker/<slug>/`에 문서를 내장한 `index.html`, `storyboard.json`, `shot-list.md`, `manifest.json`을 전달. |
| 범위 | 대본 분석, 비트·샷 계획, 블로킹과 축, 카메라 값, 입력 문서, 선택적 패널 그림, 렌더된 보드와 그 보고서. 움직이는 결과물, 브라우저 인쇄 외의 파일 내보내기는 없음. |
| 권한 | 사용자 요청과 저장소 지침 > 대본 자체의 텍스트 > 이 패키지의 기본값(`16:9`, 35 mm 센서, A4 가로 한 장에 패널 세 개, 인물 키 1.70 m) > 외부 스토리보드 가이드. |
| 근거 | 모든 패널은 원천의 비트로 추적. 모든 카메라 값은 형용사가 아니라 문서 안의 숫자. 모든 위반은 수리하거나 비어 있지 않은 `crossing.reason`과 함께 기록. 내장한 그림은 모두 `references/panel-art.md` 검사를 통과하고 `generated` 출처를 표시. 근거는 페이지 모양이 아니라 보고서 객체. |
| 도구 | 문서와 전달 폴더를 쓰는 파일 작성. 보드·보고서·인쇄용 DOM과 CSS가 있는 브라우저. 없으면 `validate`, `lint`, `render`용 `node`나 `bun` 런타임. 설치되어 있을 때 컴파일 프롬프트와 참고 이미지 없이 호출하는 `image-maker` 스킬. 없으면 선화와 저장한 프롬프트가 전달물. 네트워크 없음. |
| 루프 | 작성 → 렌더 → `getReport()` 읽기 → 오류 수정 → 경고 수리 또는 기록. 최대 두 번, 그 뒤 남은 코드를 밝히고 전달. |
| 출력 | 한국어 보드 텍스트, `index.html`, `storyboard.json`, `shot-list.md`, `manifest.json`, 그리고 그림이 있는 패널마다의 `shots[].image` 데이터 URI. 기계 판독용은 `getReport()` 객체와 `StoryboardCore` 결과. |
| 검증 | `window.storyboardStudio.getReport()` 또는 브라우저 없는 코어 실행, 그리고 `validation` 점검표와, 그림을 생성했을 때의 패널별 검사. 패키지 변경 시 코퍼스 검증기, `--require-self-containment --allow image-maker`를 붙인 저작 검증기, `bun run --cwd scripts verify`. |
| 종료 조건 | 시작 질문은 한 번만 묻고 다시 묻지 않음. 점검표와 오류 0인 보고서를 확인한 뒤 전달. 보드에 필요한 사실의 근거를 찾지 못하면 필요한 입력을 밝히고 중단. 만들지 않은 패널·인쇄·매니페스트를 만들었다고 말하지 않음. |

</instruction_contract>

<activation_examples>

긍정:

- "이 대본으로 영화 스토리보드 만들어줘. A4 가로로 인쇄할 수 있게."
- "부엌 대화 장면 6샷 콘티를 카메라 높이와 앵글 값까지 넣어서 그려줘."
- "이 줄거리로 씬마다 평면도랑 180도 검사까지 되는 선화 콘티를 만들어줘."
- "Turn this synopsis into a line-art storyboard with camera values, movement arrows, and an A4 landscape print."
- "이 장면 샷 리스트 뽑고 16:9로 패널까지 그려줘. 로우 앵글 하나 넣어줘."
- "이 대본 패널을 흑백 만화풍 그림으로 그려줘. 구도는 카메라 값대로." — 활성합니다. 런타임이 이미지를 만들 수 있으면 계산된 구도로 그림을 생성하고, 아니면 선화와 저장한 프롬프트로 대체합니다.

부정:

- "이 대본으로 애니매틱 영상 만들어줘." → 범위 밖(움직이는 결과물, 패널 아님)
- "스토리보드 느낌의 사진을 만들어줘." → 범위 밖(사진 프레임, 그린 패널 아님)
- "이 배우 얼굴 그대로 패널에 넣어줘." → 범위 밖(알아볼 수 있는 실존 인물)
- "이 영화 콘티랑 똑같이 그려줘." → 범위 밖(기존 영화 프레임 복제)
- "이 앱 화면 와이어프레임 그려줘." → 범위 밖(카메라 줄이 없는 UI 와이어프레임)

경계:

- "스토리보드 만들어줘." — 한 메시지로 원천, 화면비, 범위를 묻고, 대본이나 줄거리를 받은 뒤 활성합니다.
- "샷은 20개쯤 필요해." — 활성합니다. 샷은 10 단위로 번호를 붙이고, 씬 수는 샷 개수가 아니라 비트 시트가 정합니다.
- "카메라 각도는 대충 해도 돼." — 활성합니다. 각도는 여전히 숫자이며, 밝힌 기본값(`16:9`, 35 mm, 피치 0)이 브리프의 빈자리를 채웁니다.
- "인쇄용 PDF도 같이 줘." — 활성합니다. PDF는 브라우저 인쇄 대화상자에서만 나오고, 스킬은 PDF 파일을 만들지 않습니다.
- "그림은 내가 그릴 테니 샷 리스트만 뽑아줘." — 활성합니다. 샷 표와 문서를 전달하고 패널은 그리지 않았다고 밝힙니다.

</activation_examples>

<trigger_conditions>

요청에 스토리보드, 콘티, 샷 보드, 패널이 붙은 샷 리스트, 장면의 카메라 앵글, 시퀀스 연속성 검사, 대본을 A4로 인쇄할 보드가 나오고 결과물이 선화 패널과 카메라 값일 때 활성합니다. 사용자가 대본·줄거리·장면 목록을 주고 샷 단위로 어떻게 찍을지 물을 때도 활성합니다.

움직이는 결과물, 사진 프레임, 알아볼 수 있는 실존 인물의 얼굴, UI 와이어프레임, 기존 영화 콘티 복제 요청에는 활성하지 않으며 `routing_rule`대로 처리합니다.

</trigger_conditions>

<loop_policy>

<workflow>

두 규칙이 모든 단계에 걸립니다. 보드는 이 대본의 공간에서 만들고 다른 영화의 프레임에서 가져오지 않으며, 보드에 보이는 모든 것은 한국어로 씁니다.

| 단계 | 작업 | 산출물 |
|---|---|---|
| 1. 시작 질문 | 한 메시지로 한 번만 묻고, 브리프가 비워 둔 것만 확인합니다. 원천과 최종본 여부, 화면비, 범위와 예상 패널 수, 등장인물과 키, 톤입니다. 쓸 기본값(`16:9`, 35 mm, 페이지당 패널 세 개)을 함께 밝힙니다. | 확정된 브리프 |
| 2. 비트 분해 | 원천을 비트로 나누고 한 줄씩 적습니다. 관객이 무엇을 알게 되는지, 누가 무엇을 원하는지, 어디서 일어나는지입니다. 비트를 씬으로 묶고 대본의 헤딩과 번호를 붙이며, 씬을 뒤집는 비트를 표시합니다. | 비트 시트 |
| 3. 샷 리스트 | 비트마다 샷 하나 이상을 만들고 10 단위로 번호를 붙이며, 샷마다 크기, 초점, 존재 이유를 적습니다. 인서트는 `10`과 `20` 사이 번호인 `15`를 씁니다. | 번호 붙은 샷 리스트 |
| 4. 씬 블로킹과 축 | 인물과 소품을 평면도에 미터로 배치하고, 인물마다 방향과 포즈를 주고, 축을 만드는 두 id 또는 `null`을 선언합니다. 패널을 그리기 전에 카메라 쪽을 확인합니다. | 평면도와 축 |
| 5. 카메라 값과 의도 | `size`, `focus`, `subjects`, `yawDeg`, `rollDeg`, `focalMm`, 그리고 `pitchDeg`와 `heightM` 중 최대 하나를 적습니다. 무브, 인물 이동, 길이, 전환, 한 문장의 `intent`를 더합니다. | 샷별 숫자 |
| 6. JSON 작성 | `references/output-contract.md` §1대로 문서 하나를 조립합니다. 모든 id가 해석되고, id는 범위 안에서 겹치지 않고, 값은 열거 안에 있으며, 파일을 먼저 `storyboard.json`으로 씁니다. | `storyboard.json` |
| 7. 스튜디오 사본에 주입 | 스튜디오 자산을 `index.html`로 복사하고 문서를 `<script type="application/json" id="storyboard-doc">`에 넣으며, 모든 `</`를 `<\/`로 이스케이프합니다. 그 밖은 바꾸지 않습니다. | `index.html` |
| 8. 패널 그림 | 샷마다 `compilePanelPrompt()`로 브리프를 컴파일해 정확히 보관한 뒤, 그 문자열만 `image-maker` 스킬에 넘깁니다. `renderGuideSvg()` 가이드, 앞 패널, 캐릭터 시트, 그림체 이미지, 외부 이미지 등 참고 이미지는 어떤 것도 붙이지 않습니다. 가이드는 돌아온 그림을 `references/panel-art.md` 기준으로 검사할 때 나란히 보는 용도로만 쓰고, 모든 행을 통과한 그림만 내장합니다. 능력 관찰, 호출 두 번 한도, 거절 처리, `.hyper/image-maker/<topic>/` 저장은 image-maker가 맡습니다. image-maker가 없거나 `prompt_saved`나 `blocked`로 끝나면 선화를 두고 프롬프트를 저장합니다. 그림을 담은 문서를 `storyboard.json`에 다시 쓰고 같은 `<\/` 이스케이프로 `index.html`에 다시 주입합니다. | `shots[].image`와 다시 주입한 문서, 또는 저장한 프롬프트 |
| 9. 브라우저에서 열고 보고서 읽기 | 페이지가 아니라 `getReport()`를 읽습니다. `errors`는 빌드를 멈추고, `warnings`는 패널에 배지를 붙이고, `info`는 예상된 상태를 기록하고, `intentional`은 `crossing`을 단 샷을 다리 샷까지 모두 나열하고, 개수는 실제로 렌더된 양을 말합니다. | `getReport()` |
| 10. 오류 수정과 경고 검토 | 모든 오류를 그 `path`에서 고칩니다. 경고는 수리하고, 선 관련 경고는 `crossing`으로 기록할 수 있습니다. 한 라운드는 편집 한 번, 재렌더 한 번, 재독 한 번이며 최대 두 라운드입니다. | 정리되거나 기록된 보고서 |
| 11. 전달 | `.hyper/storyboard-maker/<slug>/`에 `index.html`, `storyboard.json`, `shot-list.md`, `manifest.json`을 쓰고 `validation` 점검표를 돌린 뒤, 폴더, 개수, 남은 코드를 밝힙니다. | 전달 폴더 |

3. 그 출력에 루프를 적용합니다. 오류를 고치고, 경고를 수리하거나 기록하며, 최대 두 라운드입니다.
4. 그 대체 실행이 `render(doc)`까지 실행해 패널과 씬 수를 셀 수 있을 때만 `manifest.json`을 쓰고, 아니면 `manifest.json` 없이 전달하며 개수를 수집하지 못했다고 밝힙니다.
5. 이미지 생성은 브라우저와 무관합니다. `image-maker`가 설치되어 있으면 샷마다 패널 그림 단계를 실행하되 같은 코어의 `compilePanelPrompt()`로 브리프를 컴파일하고 참고 이미지는 붙이지 않습니다. 설치되어 있지 않으면 선화를 두고 컴파일한 프롬프트를 `shot-list.md`에 저장합니다. 돌아와 검사하지 않은 그림을 만들었다고 말하지 않습니다.
6. 브라우저도 자바스크립트 런타임도 없으면 `storyboard.json`, `shot-list.md`, 문서를 내장한 `index.html`을 전달하고, 보고서와 시각 확인을 캡처하지 못했다는 한 줄 메모를 붙입니다. 보고서, 패널 수, 인쇄, `manifest.json`을 지어내지 않습니다.
7. 렌더하지 않은 패널의 모양을 설명하지 않고, 인쇄 대화상자를 열지 않았으면 페이지가 제대로 인쇄된다고 말하지 않습니다.

</runtime_fallback>
