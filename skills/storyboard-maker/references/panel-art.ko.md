# 패널 그림

> 영어 정본: [`panel-art.md`](panel-art.md)

패널을 선화에서 그림으로 바꾸기 전에 읽습니다. 선화는 바닥으로 남습니다. 선화가 카메라 기하, 화살표, 메모를 담당하기 때문입니다. 이 파일은 그림체, image-maker에 넘기는 고정 브리프, 패널별 절차, 돌아온 그림이 통과해야 하는 검사, 만들 수 없을 때의 대체를 다룹니다. 생성한 그림은 그리기 계약을 대신하지 않습니다. 그림은 프레임 안에 들어가고 선화의 오버레이는 그 위에 남습니다.

## 1. 그림체 목표

모든 패널 그림은 회색조 만화풍 스토리보드 잉크 선화입니다. 완성 일러스트도 사진도 아니고, 현장이 썸네일 크기에서도 읽을 수 있는 작업용 콘티입니다.

| 항목 | 목표 |
|---|---|
| 선 | 검은 잉크 윤곽선을 깨끗하게 쓰고 굵기를 조금 바꿉니다. 형태 아래쪽과 가까운 가장자리는 굵게, 안쪽은 가늘게 그립니다. 거친 연필 질감과 빗금 혼잡은 넣지 않습니다. |
| 회색 톤 | 흰색과 검은색 외에 평평한 회색을 두세 단계만 씁니다. 밝은 회색 하나가 배경과 공기를 맡고, 중간 회색 하나가 의상이나 그림자 덩어리를 맡으며, 더 어두운 회색은 예외입니다. 그라데이션, 망점, 사진 입자, 색은 넣지 않습니다. |
| 명도 분리 | 인물이 배경보다 어둡고 대비가 강하게 읽힙니다. 배경 인물은 얼굴 디테일 없는 평평한 밝은 회색 실루엣으로 그려, 사람으로는 읽히되 초점과 경쟁하지 않습니다. |
| 얼굴 | 만화식 단순화를 하되 비례는 믿을 만하게 잡습니다. 눈, 눈썹, 입이 표정을 만들고 표정은 액션 줄과 맞습니다. 얼굴을 빈 인형 머리로 두지 않습니다. |
| 실루엣 | 패널당 주동작은 하나이고, 썸네일 크기에서도 형태로 읽힙니다. 팔과 다리가 몸통과 배경 톤에 묻히지 않습니다. |
| 구도 | 패널의 화면비, 샷 크기 크롭, 인물 위치, 머리 위 여백, 바닥이 계산된 가이드를 따릅니다. 그림은 프레임을 가장자리까지 채웁니다. |
| 금지 표시 | 그림 안에 글자, 숫자, 캡션, 말풍선, 워터마크, 로고, UI, 프레임 테두리, 구분선, 화살표, 카메라 라벨을 넣지 않습니다. 패널 테두리, 이동 화살표, 패널 메모는 렌더러가 그림 둘레와 위에 그립니다. |

렌더러가 만든 프롬프트에는 이미 그림체 문장과 그림 안에 글자를 그리지 말라는 지시가 들어 있습니다. 생성 전에 컴파일된 프롬프트를 읽고, 그것과 어긋나는 그림체 문장을 덧붙이지 않습니다.

## 2. image-maker에 브리프를 넘긴다

패널 그림 생성은 `image-maker` 스킬에 위임합니다. 이미지 동작을 직접 호출하지 않고, 그 능력 검사를 여기서 다시 구현하지 않습니다. 능력 관찰, 패널별 호출 두 번 한도, 거절 처리, `.hyper/image-maker/<topic>/` 저장은 image-maker가 맡습니다.

이 스킬이 주는 것:

- 패널마다 하나의 고정 브리프. `compilePanelPrompt()`가 돌려준 정확한 문자열입니다. 이것이 지시 전체이며, 그림체 문장이나 금지 목록이나 번역을 덧붙이지 않습니다.
- 어떤 첨부도 없음. 참고 이미지, 래스터화한 가이드, 앞 패널, 캐릭터 시트, 그림체 이미지, 외부 이미지가 브리프에 붙지 않습니다.
- `renderGuideSvg()` 가이드는 스토리보드 쪽에 두고, 6절 검사에서 돌아온 그림과 나란히 봅니다. 이미지 동작에는 절대 넘기지 않습니다.

image-maker가 돌려주는 것:

- 생성한 그림. 이 스킬이 검사한 뒤 내장합니다.
- `prompt_saved` 또는 `blocked`. 선화를 유지하고 8절로 보냅니다.
- 스킬이 설치되어 있지 않아 그림이 없음. 역시 8절로 보냅니다.

패널별 결과를 `generated`, `prompt_saved`, `blocked` 중 하나로 전달 보고에 적습니다. 제품 이름이나 문서의 언급이나 이전 실행을 지금 그림이 있다는 증거로 승격하지 않습니다.

## 3. 패널 하나씩 처리한다

패널은 샷 순서대로 처리합니다. 돌아온 그림은 문서 하나와 브리프 하나를 기준으로 검사하기 때문입니다. 패널마다 다음을 수행합니다.

1. **구도를 계산한다.** `layoutShot(doc, sceneId, shotId)`를 호출하고 돌려받은 `pitchDeg`, `heightM`, `facingScreen`, `angleName`, `yawName`을 보관합니다. 그림이 맞춰야 하는 값은 대본의 서술이 아니라 이 값입니다. `facingScreen`은 초점이 인물일 때만 적용하고, 소품만 잡는 인서트에는 보는 방향이 없습니다.
2. **가이드를 렌더한다.** `renderGuideSvg(doc, sceneId, shotId)`를 호출하고 돌려받은 SVG 문자열을 보관합니다. 가이드에는 인형, 바닥 격자, 지평선만 있고 화살표, 라벨, 메모는 없습니다. 빈 문자열이 오면 씬이나 샷 id가 틀린 것이므로 멈추고 문서를 고칩니다. 가이드는 검사자가 보는 구도 참고이며 스토리보드 쪽에 둡니다.
3. **브리프를 컴파일한다.** `compilePanelPrompt(doc, sceneId, shotId)`를 호출하고 정확한 문자열을 보관합니다. 컴파일러는 샷 크기, 각도와 도수, 초점이 인물일 때의 보는 방향, 렌즈, 화면에 보이는 인물의 `look`, 액션 텍스트, 그림체 문장을 넣고 대사는 빼며 그림 안에 글자를 그리지 말라고 지시합니다. 사실 오류가 없는지 한 번 읽고, 그 뒤에는 바꾸지 않습니다.
4. **image-maker를 호출한다.** 컴파일한 문자열만 브리프로 넘기고 아무것도 붙이지 않습니다. 동작이 참고 이미지를 받더라도 어떤 참고 이미지도 허용하지 않습니다. 인물 일관성은 브리프 안의 `look` 문구가 전달합니다.
5. **검수한다.** 돌아받은 그림을 읽을 수 있는 크기로 가이드와 나란히 보고 6절의 검사를 모두 수행합니다. 떨어진 그림은 넣지 않고, image-maker의 남은 허용량 안에서만 다시 호출하며, 아니면 대체합니다.
6. **넣는다.** 통과한 그림을 7절 방식으로 `shots[].image`에 쓰고 다음 샷으로 넘어갑니다.

패널을 모두 한꺼번에 생성하고 나중에 검수하지 않습니다. 네 번째 패널에서 발견한 디자인 흐름의 어긋남은 다섯 번째와 여섯 번째가 물려받기 전에 고치는 편이 쌉니다. 직접 이미지 동작을 쓸 수 있어 보인다고 image-maker를 건너뛰지 않습니다. 그러면 능력 기록, 호출 한도, 거절 처리를 잃습니다.

## 4. 카메라 값이 프롬프트 문구가 되는 방식

프롬프트는 영어로 쓰고 카메라 기하를 평범한 촬영 언어로 적습니다. 숫자는 패널의 카메라 줄과 대조할 수 있게 문구에 남깁니다. 컴파일된 문자열은 고정된 문장 순서를 따릅니다.

```text
Storyboard panel, <size>[, <view>]. Camera <angle> <degrees>°, <height> height <metres> m, <focal>mm lens[, dutch angle, horizon tilted <degrees>° to the <right|left>].
[<count> characters in frame: <name> (<look>); ... | Characters: <name> (<look>).]
Action: <action>. [Props in frame: <labels>.] Style: <style>.
Do not draw any text, letters, numbers, captions, or speech bubbles in the image.
```

아래 표는 입력마다 컴파일러가 내는 정확한 조각입니다. 컴파일된 프롬프트를 이 표와 대조해 읽고, 생성 전에 문구를 바꿔 쓰지 않습니다.

| 카메라 값 | 프롬프트 문구 |
|---|---|
| `size: ECU` | `extreme close-up` |
| `size: CU` | `close-up` |
| `size: MCU` | `medium close-up` |
| `size: MS` | `medium shot` |
| `size: COWBOY` | `cowboy shot` |
| `size: MWS` | `medium wide shot` |
| `size: FS` | `full shot` |
| `size: WS` | `wide shot` |
| `size: ELS` | `extreme wide shot` |
| `size: OTS` | `over-the-shoulder shot` |
| `yawDeg` FRONT | `front view, subject faces the camera` |
| `yawDeg` 3/4 | `three-quarter view, subject facing screen-left` 또는 `three-quarter view, subject facing screen-right` |
| `yawDeg` PROFILE | `profile view (side view), subject facing screen-left` 또는 `profile view (side view), subject facing screen-right` |
| `yawDeg` 3/4 BACK | `three-quarter back view, face mostly hidden` |
| `yawDeg` BACK | `back view, subject's face not visible` |
| `pitchDeg` 0 | `eye level 0°` |
| `pitchDeg` -12 | `low angle 12°` |
| `pitchDeg` +30 | `high angle 30°` |
| `pitchDeg` +90 | `overhead 90°` |
| `heightM` ≤ 0.3 또는 `pitchDeg` ≤ -75 | `worm's eye <degrees>°` |
| `heightName` KNEE, 0.5 m | `knee height 0.50 m` |
| `heightName` SHOULDER, 1.3 m | `shoulder height 1.30 m` |
| `heightName` ABOVE, 2.1 m | `above height 2.10 m` |
| `rollDeg` +8 | `dutch angle, horizon tilted 8° to the right` |
| `rollDeg` -8 | `dutch angle, horizon tilted 8° to the left` |
| `focalMm` 24 | `24mm lens` |
| `focalMm` 50 | `50mm lens` |
| `focalMm` 85 | `85mm lens` |
| `subjects` 둘 | `2 characters in frame: <name> (<look>); <name> (<look>)` |

샷 크기와 뷰 조각이 첫 문장을 열고, 앵글·높이·렌즈 조각이 둘째 문장을 이루며 롤 조각이 그 문장을 이어 갑니다. 뷰 조각은 초점이 인물일 때만 나옵니다. 롤은 소수 한 자리로 적고 정수면 소수점 없이 적습니다.

문구 규칙 두 가지:

- 렌즈 문구는 화각만 이름 붙입니다. 짧은 렌즈 자체가 얼굴을 왜곡한다고 쓰지 않습니다. 원근은 거리가 정하고, 광각이 과장하는 것은 프레임을 채우려고 카메라가 얼굴에 가까워지기 때문입니다.
- 프롬프트는 프레임의 시작 구도를 설명합니다. 무브는 오버레이의 화살표와 라벨로 남고, 움직이는 카메라는 그림에 모션 블러, 속도선, 두 번째 프레임을 더하지 않습니다.

## 5. 패널 사이 인물 일관성

인물은 모든 패널에서 같은 사람으로 보여야 합니다. 일관성은 붙인 그림이 아니라 고정 문구에서 나옵니다.

- `characters[].look`이 디자인 계약입니다. 나이대, 체형, 머리 모양과 길이, 의상, 구별되는 특징 하나둘을 색이 아니라 모양과 회색 값으로 적습니다. 예를 들어 "짧은 검은 머리, 마른 체형, 어두운 회색 후드 재킷, 왼쪽 눈썹 위의 얇은 흉터"입니다. 컴파일러는 그 인물이 나오는 모든 프롬프트에 이 문구를 그대로 복사합니다.
- 패널 사이에 `look` 문구를 바꿔 쓰거나 줄이거나 다시 꾸미지 않습니다. 설명이 바뀌면 얼굴도 바뀝니다.
- 컴파일된 `look` 문구가 유일한 정체성 전달 수단입니다. 캐릭터 시트, 앞 패널, 생성한 초상화를 어떤 호출에도 붙이지 않습니다.
- 문서에 없는 의상 변경, 머리 모양 변경, 새 주요 인물을 모델이 만들게 두지 않습니다. 배경 인물은 단순한 실루엣이어도 되지만 추가 주요 인물로 읽히면 안 됩니다.
- 돌아온 그림이 `look` 문구에서 벗어나면 검사 실패로 보고, 그림을 붙여 고치지 않고 대체합니다.

## 6. 넣기 전 검수

돌려받은 그림은 취향이 아니라 문서와 대조해 검수합니다. 모든 행을 통과해야 넣습니다.

| 검사 | 통과 조건 | 실패 시 |
|---|---|---|
| 샷 크기 | 크롭이 `size`와 맞습니다. `CU`는 머리와 목, `MS`는 허리 위, `FS`는 머리 위 여백과 약간의 바닥을 포함한 전신입니다. | image-maker의 허용량 안에서 다시 호출, 그 뒤 대체. |
| 앵글 | 피치 부호가 보입니다. 앙각은 턱 아래와 올라가는 지평선, 부감은 정수리와 내려가는 지평선, 오버헤드는 지평선 없음입니다. | image-maker의 허용량 안에서 다시 호출, 그 뒤 대체. |
| 뷰 | 초점이 인물이면 뷰가 `yawName`과 프롬프트의 뷰 조각에 맞습니다. 정면, 3/4, 측면, 3/4 뒷모습, 뒷모습 중 하나이고 뒷모습에서는 얼굴이 보이지 않습니다. | image-maker의 허용량 안에서 다시 호출, 그 뒤 대체. |
| 사각 | `rollDeg`가 0이 아니면 말한 만큼 기울고 방향이 부호와 맞습니다. 양수 롤은 지평선이 오른쪽으로 내려가고 음수 롤은 왼쪽으로 내려갑니다. 롤이 0이면 지평선이 수평입니다. | image-maker의 허용량 안에서 다시 호출, 그 뒤 대체. |
| 보는 방향 | 초점이 인물이고 `yawName`이 3/4 또는 PROFILE일 때만 적용합니다. 프롬프트가 방향을 말하는 뷰가 이 둘뿐입니다. 인물이 `layoutShot().facingScreen` 쪽, 즉 화면 왼쪽이나 화면 오른쪽을 봅니다. FRONT, 3/4 BACK, BACK은 뷰 행이 대신 확인합니다. 카메라 쪽 얼굴, 얼굴이 거의 가려짐, 얼굴이 보이지 않음입니다. 소품만 잡는 인서트는 이 행을 건너뜁니다. 더 예뻐도 좌우가 뒤집힌 그림은 실패입니다. | image-maker의 허용량 안에서 다시 호출, 그 뒤 대체. |

## 7. 넣기와 출처 표시

통과한 그림만 넣습니다. 샷에 data URI로 저장하고, 정확한 컴파일 프롬프트와 정직한 출처를 함께 적습니다.

```json
"image": {
  "src": "data:image/png;base64,<base64 바이트>",
  "provenance": "generated",
  "prompt": "<compilePanelPrompt가 돌려준 정확한 문자열>"
}
```

규칙:

- `src`는 `data:image/png`, `data:image/jpeg`, `data:image/webp` URI입니다. `http`나 `https` URL, 파일 경로, blob URL은 안 됩니다. 패널은 네트워크 없이 렌더되어야 합니다. 돌려받은 바이트를 변환하고 링크하지 않습니다.
- `provenance`는 이번 실행의 이미지 동작이 그림을 돌려줬을 때만 `generated`입니다. 사용자가 제공한 그림은 `supplied`이고, 절대 generated라고 부르지 않으며 프롬프트의 결과로 제시하지 않습니다.
- `prompt`는 컴파일된 문자열 그대로입니다. 줄인 요약, 번역문, 재시도의 두 번째 프롬프트를 저장하지 않습니다. 재시도는 같은 문구를 쓰기 때문입니다.
- HTML을 다루기 쉬운 크기로 유지하되, 실패한 검사를 숨기려고 그림을 자르지 않습니다. 줄여야 하면 프레임 전체를 줄입니다.
- 전달 보고는 어느 패널이 생성되었고 어느 패널이 제공되었고 어느 패널이 선화로 남았는지 적습니다. 패널 id 없는 개수는 증거가 아닙니다.

## 8. 실패와 대체

다음 중 하나면 선화 패널로 대체합니다.

- `image-maker`가 설치되어 있지 않습니다.
- `image-maker`가 `prompt_saved` 또는 `blocked`로 끝났습니다.
- image-maker의 허용량 안에서 통과한 그림이 돌아오지 않았습니다.

대체는 보드의 실패가 아닙니다. 선화는 이미 카메라 기하와 무브와 메모를 담고 있고, 그림은 추가물입니다.

대체할 때:

1. `shots[].image`를 비워 둡니다. 자리표시자, 깨진 data URI, 가이드 래스터를 그림인 척 넣지 않습니다.
2. 대체 패널의 프롬프트는 `shot-list.md`에 둡니다. 샷의 비고를 `PROMPT SAVED`로 표시하고 표 뒤에 `SH <id>` 블록으로 프롬프트를 다시 적습니다. 생성한 패널은 정확한 프롬프트를 `shots[].image.prompt`에 보관합니다. `manifest.json`은 바뀌지 않은 `getReport()` 객체이며 프롬프트를 담지 않습니다. 나중 실행이 같은 그림을 만들 수 있도록 프롬프트가 남아야 합니다.
3. 패널 id와 원인으로 대체를 보고합니다. 예를 들어 "SH 30: image-maker prompt_saved, 선화 유지, 프롬프트 저장"입니다.
4. 프롬프트만 남았을 때 이미지가 생성되었거나 저장되었거나 첨부되었다고 말하지 않습니다.

보드는 생성된 패널과 선화 패널을 섞어 가질 수 있습니다. 정상적인 부분 결과이고 패널별로 보고합니다. 한 패널이 대체되었다고 보드 전체를 다시 생성하지 않습니다.

## 9. 안전과 이미지 출처

- 실존 인물, 연예인, 알아볼 수 있는 얼굴을 그리지 않습니다. 대본이 실존 인물을 지목하면 그 역할의 가상 인물로 그립니다. 서술된 의상과 체형은 따르되 얼굴은 따르지 않습니다.
- 기존 영화의 프레임, 콘티, 홍보 이미지를 복제하지 않습니다. 대본이 그 영화를 톤의 참고로 언급해도 영화 스틸, 포스터, 프레임 캡처를 참고 이미지로 넣지 않습니다.
- 참고 이미지는 파이프라인에 들어가지 않습니다. 가이드는 검사할 때 돌아온 그림과 나란히 볼 뿐 절대 붙이지 않고, 앞 패널, 캐릭터 시트, 그림체 이미지, 외부 이미지도 붙이지 않습니다.
- 생성한 그림은 `provenance`와 전달 보고에서 생성으로 표시합니다. 제공받은 그림은 `supplied`로 표시합니다. 어느 쪽도 사진이나 실제 제작 프레임이라고 설명하지 않습니다.
- image-maker의 거절은 최종으로 존중합니다. 문서가 바뀔 때만 요청을 바꾸고, 거절된 소재를 부드러운 말로 바꿔 숨기지 않습니다.

| 검수 전에 모든 패널을 생성 | 디자인 어긋남이 시퀀스 전체에 반복됩니다. | 다음 패널 전에 패널마다 검수합니다. |
| 영화 스틸을 그림체 참고로 씀 | 기존 작품을 베끼고 보호된 프레임을 재현할 수 있습니다. | 참고 이미지를 하나도 붙이지 않고 컴파일한 브리프만 입력으로 씁니다. |
