# 이미지 슬롯과 생성 프롬프트

> 영어 원본: [`image-slots.md`](image-slots.md)

**목적**: 글 한 편에 이미지가 몇 개 들어가고, 각각 어디에 놓이고, 어떤 것은 작성자가 찍어야 하고 어떤 것은 AI로 만들어도 되는지, 그리고 생성하는 이미지마다 붙는 복사용 프롬프트를 정합니다. 마커 문법은 여기서 고정합니다. 각 이미지가 무엇을 증명해야 하는지는 [`topic-research.ko.md`](topic-research.ko.md) §5가 정하고, JSON 템플릿은 [`../references/image-prompt-templates.ko.md`](../references/image-prompt-templates.ko.md)에 있습니다.

## 1. 밀도 (관측 기본값)

사용자가 목표 느낌으로 준 레퍼런스 글 2편(2026년 9월, 전환형 B2B, `evidence-digest.ko.md` T4/T10 메모)을 재보니 1,477자에 이미지 28장, 1,012자에 25장이었고 각각 15~16개 이미지 블록으로 묶여 있었습니다. 25~250자(가운데 정렬 2~4줄) 텍스트 뒤에 이미지 블록, 이것을 끝까지 반복합니다. 블록은 단일 사진, 2~8장 콜라주, 그리고 원리를 설명하는 지점의 설명 다이어그램 1장이 섞여 있습니다.

여기서 끌어낸 기본값(관측치이고 강제 아님. `naver-ranking-contract.ko.md`의 속설 규칙은 그대로 적용):

| 글 길이 | 이미지 블록 | 배치 리듬 |
|---|---|---|
| 1,000자 이하 | 8~12 | 본문 80~120자마다 블록 하나 |
| 1,000~2,000자 | 12~18 | 2~4줄 단락마다 블록 하나 |
| 2,000~3,000자 | 16~24 | 같음. 블록 없이 300자를 넘기지 않음 |

계획 기준은 커버와 섹션별 시각 자료이며 아쉬운 점 섹션도 검토합니다. 설명에 보탬이 없는 이미지는 수량을 맞추려고 넣지 않습니다. 기본값보다 적으면 이유를 발행 메모에 적습니다.

## 2. 마커 문법

블록 하나는 본문의 정확한 위치에 있는 인라인 마커 하나입니다. 두 종류입니다.

```
[이미지: 무엇을 찍을지 | 캡션]                      ← 작성자가 찍거나 이미 가진 것
[이미지 생성: 무엇을 그릴지 | 캡션 | 프롬프트 #n]     ← AI 생성. 글 블록 뒤에 JSON 프롬프트 #n이 따라옴
```

- 콜라주는 안에 든 컷을 적은 마커 하나입니다. `[이미지: 콜라주 3장 — 바닥 물고임 / 천장 얼룩 / 벗겨진 도장면 | 같은 주차장 B2층, 2026년 8월]`.
- 캡션은 사진이 뒷받침하는 사실을 말하고 라벨을 쓰지 않습니다.
- 마커 다음 문장이 마커를 가리켜도 됩니다(`위 단면도처럼…`).

## 3. 생성해도 되는 것

| 생성(`이미지 생성`) | 절대 생성하지 않음(`이미지`) |
|---|---|
| 원리를 설명하는 섹션 전환 일러스트(단면, 흐름, 전후 도식) | 글이 실제라고 주장하는 제품, 장소, 영수증, 견적서, 계기 수치, 결과 |
| 실제 커버 사진이 없을 때의 커버 아트(캡션에 일러스트라고 표기) | 브랜드 로고, 인증서, 자격증, 서류 |
| 이미지로 그린 비교표, 아이콘 열, 체크리스트 | 작성자·직원·고객으로 보이는 사람 |
| 추상 섹션(위험, 시기, 비용 구조)의 분위기·개념 이미지 | 독자가 사실의 사진 증거로 받아들일 만한 모든 것 |

생성 이미지는 증거 사진을 대신하지 못합니다. 증거 사진이 없으면 마커는 `[이미지: …]`로 남고 발행 전 메모에 적습니다. 전환형도 실제 주장에 필요한 증거 사진만 요구하며 고정된 실제 사진 비율을 강제하지 않습니다. 없는 자료는 발행 메모에 적습니다.

## 4. 프롬프트 블록

글 블록 뒤에 `이미지 생성` 마커마다 블록 하나를 `프롬프트 #n` 번호에 맞춰 전달하고 `../references/image-prompt-templates.ko.md`의 템플릿으로 만듭니다. 여는 펜스에는 `json` 언어 태그를 반드시 붙입니다. 태그 없는 맨 펜스는 소비자가 블록을 안정적으로 찾을 수 없으므로 허용하지 않습니다. 각각은 구조화된 자연어 요청을 받는 이미지 도구에 붙일 완결된 브리프이며 API 요청 형식 호환성을 보장하지 않습니다. 제공자 플래그, 모델 이름, 자리표시자 없음. 이미지 안에 들어갈 한국어 글자(다이어그램 라벨)는 나타나야 할 그대로 한 번만 적습니다.

`post-workflow.ko.md` §5의 전달 순서: 제목 → 글 블록 → **프롬프트 블록** → 검색어 줄 → 슬롯 목록 → 발행 전 메모.

## 5. 말투 맞추기

시작 질문의 블로그 URL을 읽을 수 있었으면 최근 글 3편의 글당 이미지 수를 세고 §1에서 가장 가까운 행을 고릅니다. 블로그 자신의 습관이 기본값보다 우선합니다. 잰 숫자를 발행 전 메모에 적습니다.

## 6. 완결된 시각 브리프 작성

이 절이 컴파일 정책을 소유합니다. 필드 설명과 열네 개 섹션 역할, 열일곱 개 템플릿 ID는 [`../references/image-prompt-templates.ko.md`](../references/image-prompt-templates.ko.md)가 소유합니다. **아래 모든 스키마·템플릿 판단보다 §3이 우선합니다.** 어떤 역할이나 템플릿도 §3이 금지한 대상을 생성하도록 허가하지 않습니다. 이 절은 §7의 프롬프트 전달 기본값을 바꾸지 않습니다.

슬롯마다 실제 자료인지 설명용 생성물인지 먼저 분류하고 역할과 템플릿을 정한 뒤(§3, [`topic-research.ko.md`](topic-research.ko.md) §5), 다음 순서로 컴파일합니다.

`use → section_role / template → hierarchy → subject → scene → composition → lighting → color → material_and_rendering → text → series_invariants → must_include / must_exclude → inspection_checks → aspect → caption_note → prompt`

- **목적 하나, 시선 순서 하나.** 이미지마다 목적 하나를 정하고 `hierarchy`에 첫째 → 둘째 → 배경의 읽기 순서를 명시합니다. “고급스럽게”, “아름답게” 대신 대상의 특징, 동작, 환경, 시점, 크기, 잘리는 범위, 깊이, 여백을 설명합니다.
- **속성은 제 필드로 보냅니다.** `style`은 매체와 그림 언어, 선과 형태 언어만 담습니다. 팔레트 역할(주조색·보조색·강조색과 읽기에 필요한 대비)은 `color`로, 표면 반응·모서리 거동·질감은 `material_and_rendering`으로, 빛의 방향·부드러움·그림자·분리는 `lighting`으로 보냅니다. 적용되지 않는 필드는 자리표시자로 채우지 않고 생략합니다. `null`, `"N/A"`, `"없음"`, `"위와 동일"`은 쓸 수 없습니다.
- **요청한 글자는 그대로 보존합니다.** 각 `text[].string`은 `text[]` 안에서 정확히 한 번 나타나며 같은 라벨을 두 번 나열하지 않습니다. `prompt`는 그 문구를 하나도 빠뜨리지 않고 byte 단위로 그대로 담아 붙여넣은 문장이 그 라벨들을 그대로 그리게 합니다. `prompt`의 설명 문장이 같은 단어를 다시 쓸 수는 있지만, `text[]`에 없는 라벨을 새로 만들어 내서는 안 됩니다. 위치, 읽는 순서, 우선순위, 크기, 대비, 주변 여백도 지정합니다. 어느 한 표현 안에서 번역·축약·교정하지 않습니다. `text[]` 안에서는 같은 라벨을 두 번 나열하지 않고, `prompt` 안에서는 각 문구가 그대로 나타나야 하며 주변 설명 문장은 같은 단어를 자유롭게 다시 써도 됩니다. 다만 `prompt`가 `text[]`에 없는 라벨을 새로 담아서는 안 됩니다. 맞춤법을 지시했다고 실제 이미지의 글자가 정확하다는 뜻은 아닙니다.
- **시리즈 공통 조건은 진짜 시리즈일 때만.** 두 장 이상을 **하나의 시리즈**로 의도했을 때만 그 시리즈의 공통 조건(팔레트 역할, 그림체, 선 굵기, 글자 처리, 조명과 재질 표현)을 시리즈의 모든 객체에 같게 반복합니다. 역할이 다른 독립 이미지에는 `series_invariants`를 아예 넣지 않습니다. 하나만 복사해도 완결돼야 하므로 “위와 동일”이라고 쓰지 않습니다. 이미지별 대상이나 구도만 바꿉니다.
- **참조 경계를 밝힙니다.** 제공된 자료가 있으면 `reference.role`로 분위기 참고인지 편집 원본인지 구분합니다. 편집 프롬프트에는 원본, 보존할 요소, 바꿀 범위를 적습니다. 정체성이나 보존 조건을 지어내지 않습니다. 해결되지 않은 원본 요구 사항은 복사용 프롬프트 밖에 둡니다.
- **막힌 빈칸과 되돌릴 수 있는 가정을 나눕니다.** 주제, 정확히 그려질 글자, 편집의 보존·변경 경계가 비어 있으면 그 이미지의 완성 프롬프트를 내지 않습니다. 물어보거나 슬롯을 열어 둡니다. 되돌릴 수 있는 표현 선택(크롭, 팔레트 압력, 여백)은 실행자가 정하고 `assumptions`에 기록합니다. 글 자체가 모르는 사실은 `[확인 필요]` 슬롯으로 남습니다.
- **무엇을 확인할지 적습니다.** `inspection_checks`에는 반환된 결과물과 대조할 관찰 가능한 기준 3~6개를 둡니다. 시선 순서, 대상의 사실, 정확한 글자, 팔레트 역할, 재질, 시리즈 통일성이 대상입니다.
- **컴파일 경계를 지킵니다.** 도구명, 모델명, API 매개변수, 제공자 플래그, 파일 경로, 상태 보고, 기능 지원 주장은 시각 브리프 밖에 둡니다. 여기의 JSON은 그림을 설명하는 휴대 가능한 브리프이지 모든 이미지 API에 통하는 스키마가 아닙니다. `prompt`는 구조 필드에서만 파생하고 새 사실을 더하지 않습니다.

## 7. 프롬프트 전달과 이미지 생성 구분

이 흐름은 생성 이미지가 아니라 프롬프트를 전달합니다. 마커가 있다는 이유만으로 이미지 서비스를 호출하지 않습니다. 생성을 별도로 요청받으면 현재 사용 가능한 생성·편집 기능과 권한부터 확인합니다. 참고 URL이 기능이나 권한을 보장하지 않습니다. 원본을 보존하는 편집을 신규 생성으로 대신하지 않고 원본은 그대로 둡니다.

실제 반환된 이미지가 확인된 뒤에만 이미지가 있다고 말합니다. 시각적 성공을 주장하기 전에 시선 순서, 대상의 사실, 구도, 조명, 팔레트, 재질, 정확한 글자, 시리즈 통일성을 확인합니다. 이미지를 볼 수 없으면 이 항목들은 미검증이라고 밝힙니다. 제공자 이름이나 과거 실행으로 현재 기능을 추정하지 않습니다.
