# 런타임 프리미티브

> 영어판: [`runtime-primitives.md`](runtime-primitives.md)

각 런타임이 실제로 제공하는 기능, 그 기능의 상태 표기, 문서화된 한도다. 루프에 호출 문법을 적기 전에 이 문서를 읽고, 다른 런타임이 같은 방식으로 동작한다고 가정하기 전에 다시 읽는다.

아래 상태와 한도는 2026-11-03에 읽었다. 벤더 기능은 이 표보다 빠르게 움직인다. 출처 열이 있는 이유는 오래된 행을 논쟁 대상이 아니라 확인 대상으로 만들기 위해서다.

## 기능 대응표

| 기능 | Claude Code | Codex | LangChain |
|---|---|---|---|
| 조건이 성립할 때까지 반복 | `/goal`. 세션 범위, 모델 평가 | `/goal`. 유지되는 목적 | `create_agent`와 미들웨어 |
| 간격으로 반복 | `/loop`(로컬), 클라우드 예약 작업 | 시간 일정이 있는 자동화 | 배포 cron |
| 외부 이벤트로 시작 | 예약 작업의 API·GitHub 트리거 | 자동화의 Gmail·Slack·GitHub 이벤트 | 배포 웹훅, 채널 |
| 독립 검사 | 프롬프트 유형 정지 훅, `/goal` 평가자 | 문서화된 평가자 기능 없음 | `RubricMiddleware`, `after_agent` 훅, 결정적 채점자 |
| 병렬 격리 | Git 워크트리, 서브에이전트, 동적 워크플로 | 스레드별 워크트리(실무자 서술) | 프로세스 수준. 직접 설계한다 |
| 상태 유지 | 저장소 안 파일(직접 설계) | `AGENTS.md`와 파일(직접 설계) | 파일 또는 저장소(직접 설계) |
| 강제 상한 | 조건의 턴 수, 에이전트 수, 작업 수 | 공급자 측 사용 한도 | 직접 작성한 코드 |
| 관측 | `/usage`, `/workflows`, 대화 기록의 판정 | 실행 이력과 결과 인박스 | 플랫폼 트레이스 |
| 사람 없는 실행의 권한 모델 | 권한 모드, 샌드박스, 훅 | 샌드박스 정책과 승인 정책 | 배포 방식에 따름 |

이 표에서 두 행은 모든 런타임에서 "직접 설계"다. 상태와 상한은 설치하는 기능이 아니라 직접 붙이는 부품이다. 루트 계약이 이 둘을 벤더 기능이 아니라 필수 구성 요소로 다루는 이유다.

## Claude Code

| 프리미티브 | 하는 일 | 상태·한도 |
|---|---|---|
| `/goal <조건>` | 턴이 끝날 때마다 조건과 대화 기록을 작은 고속 모델에 보내고, 아직 아님·충족·불가능 판정과 이유를 받는다 | 세션당 목표 하나. 조건 4,000자까지. 평가자는 도구가 없음. 도구 사용 없는 턴이 여러 번 이어지면 진전 없음으로 정지 |
| `/loop <간격> <프롬프트>` | 현재 세션 안에서 프롬프트를 간격마다 다시 실행한다 | 번들 스킬. 최소 간격 1분. 세션이 열려 있고 유휴일 때만 발동. 세션당 작업 50개. 반복 작업은 7일 뒤 만료. 놓친 실행을 따라잡지 않음 |
| 클라우드 예약 작업(`/schedule`, 구 루틴) | 프롬프트, 저장소, 커넥터를 묶은 설정을 Anthropic 관리 인프라에서 실행한다 | **연구 프리뷰.** "동작, 한도, API 표면이 바뀔 수 있다". 트리거는 일정·API·GitHub. 계정당 시간당 예약 실행 100회, 작업당 run-now·API·1회성 합계 시간당 30회, 계정당 시간당 API 발동 100회, 초과 허용 없음 |
| 동적 워크플로 | Claude가 작성한 JavaScript 스크립트가 서브에이전트를 오케스트레이션하고, 루프와 분기와 중간 결과를 스크립트가 보유한다 | 페이지에 프리뷰 표기 없음. 유료 플랜과 API, 클라우드 공급자에서 사용 가능. 실행당 에이전트 1,000개, 기본 동시 16개, parallel·pipeline 호출당 항목 4,096개. 재개 시 완료된 에이전트는 캐시에서 재생 |
| 권한 모드 | 분류기 기반 `auto`를 포함한 여섯 가지 모드 | `auto`는 "권한 프롬프트를 줄이지만 안전을 보장하지는 않는다" |
| 정지 훅(프롬프트 유형) | 턴이 끝날 때 도는 모델 평가 검사. `/goal`은 그 위의 세션 범위 래퍼다 | 기본 타임아웃 30초. 별도 지정이 없으면 백그라운드 모델에서 실행 |
| 워크트리 | 세션마다 별도 작업 디렉터리와 브랜치. 저장소 이력은 공유한다 | 파일 편집을 격리한다. `.git` 디렉터리나 외부 부수 효과는 격리하지 않는다 |

표보다 중요한 구현 메모가 셋이다. 첫째, `/loop`는 열린 세션이 필요하다. "작업은 Claude Code가 실행 중이고 유휴일 때만 발동"하므로 워크스테이션 프리미티브이지 운영 스케줄러가 아니다. 둘째, 클라우드 예약 작업은 연구 프리뷰이므로 베타 헤더와 `/fire` 엔드포인트를 포함한 API 표면은 안정된 계약이 아니다. 셋째, `/goal`은 정책으로 훅이 비활성화되면 사용할 수 없다고 문서화돼 있다. 평가자가 훅 시스템의 일부이기 때문이다. 평가자에 의존하는 루프는 훅 권한 모델을 함께 물려받는다.

## Codex

| 프리미티브 | 하는 일 | 문서화된 동작 |
|---|---|---|
| `/goal <목적>` | 활성 대화에 유지되는 목적을 붙인다. `/goal edit`, `/goal pause`, `/goal resume`, `/goal clear` | 목적은 비어 있으면 안 되고 4,000자까지. "목표 텍스트가 첫 프롬프트이자 완료 기준이 된다". 더 넓은 접근 권한을 주지 않는다 |
| 자동화 | 예약 또는 이벤트 트리거 작업. 결과는 Scheduled 인박스에 쌓인다 | 이벤트 트리거는 웹과 모바일에서 쓸 수 있고 "데스크톱 앱, Codex CLI, IDE 확장에서는 쓸 수 없다". 한 작업이 여러 이벤트 트리거를 쓸 수 있지만 "이벤트 트리거와 시간 기반 일정을 결합할 수는 없다". 사용자 지정 주기는 RFC 5545 반복 규칙 |
| 샌드박스 정책 | `read-only`, `workspace-write`, `danger-full-access` | 명령 실행 중 파일 시스템과 네트워크 접근을 규율한다 |
| 승인 정책 | `on-request`, `never`, 또는 세분화 형태 | `untrusted`는 지원되지 않는 것으로 문서화돼 있고, 클라이언트 시작을 막을 수 있다 |

이식에서 중요한 차이는 이것이다. 이 개정판 문서 기준으로 Codex의 `/goal`은 **유지되는 목적**이지 평가자 모델이 붙은 계속 실행 루프가 아니다. 문서에는 판정 상태, 턴 카운터, 토큰 표시가 없고, 문서 전체에서 "run until"을 찾으면 아무것도 나오지 않는다. Claude Code의 `/goal` 의미론에 맞춰 쓴 루프는 그쪽에 직접 대응물이 없다. 가장 가까운 구성은 프롬프트에 완료 기준을 적은 자동화다.

## LangChain

| 프리미티브 | 루프에서의 역할 | 문서화된 동작 |
|---|---|---|
| `create_agent` | 에이전트 루프 | 모델이 작업이 끝날 때까지 도구를 반복 호출한다 |
| `RubricMiddleware` 또는 `after_agent` 훅 | 검증 루프 | 채점자가 산출물을 기준표와 대조하고, 실패하면 피드백과 함께 되돌려보낸다. 채점자는 결정적일 수도 에이전트형일 수도 있다 |
| 배포 cron, 웹훅, 채널 | 이벤트 기반 루프 | 외부 이벤트나 일정이 실행을 시작한다 |
| LangSmith Engine | 언덕 오르기 루프 | 분석 에이전트가 운영 트레이스를 읽고 하네스 설정을 고쳐 쓴다 |

프레임워크 자신의 정리는 검증 계층이 "실행마다 지연과 비용을 늘린다"는 것이고, 켜기 전에 값을 매겨야 할 거래다(2026-11-03 확인).

## 설계에 반영할 문서화된 한도

| 한도 | 값 | 런타임 |
|---|---|---|
| 조건 또는 목적 길이 | 4,000자 | Claude Code `/goal`, Codex `/goal` |
| 최소 간격 | 1분 | Claude Code `/loop` |
| 예약 작업 수명 | 반복 작업 7일 | Claude Code `/loop` |
| 세션당 작업 수 | 50 | Claude Code `/loop` |
| 클라우드 예약 실행 | 계정당 시간당 100회, 작업당 시간당 30회 | Claude Code 예약 작업 |
| 워크플로 실행당 에이전트 | 1,000개 | Claude Code 워크플로 |
| 동시 워크플로 에이전트 | 기본 16개, 1~256 설정 | Claude Code 워크플로 |
| `parallel()`·`pipeline()` 호출당 항목 | 4,096개 | Claude Code 워크플로 |
| 일시정지 전 자동 재시도 | 3회 | Claude Code `/goal` |
| 백그라운드 작업 체크인 간격 | 30분에서 1시간, 2시간으로 배증. 목표당 유휴 체크인 최대 3회 | Claude Code `/goal` |

이 숫자를 잡학이 아니라 설계 제약으로 읽는다. 시간당 200회를 예약하는 루프는 조용히 상한에 걸린다. 노트북을 닫아도 살아야 하는 `/loop` 작업은 살아남지 못한다. 2,000개 항목 팬아웃은 거부되며, 올바른 설계는 상한을 올리는 것이 아니라 작업을 나누는 것이다.

## 이식 규칙

1. **문법보다 기능을 먼저 본다.** 루프를 트리거 → 작업 공급원 → 검사 → 상한 → 에스컬레이션으로 쓰고, 그다음 각 부분을 런타임에 대응시킨다. 한 벤더의 문법으로만 존재하는 루프는 옮길 수 없다.
2. **같은 이름이 같은 동작이라고 가정하지 않는다.** 두 런타임이 `/goal`을 제공하지만, 하나는 턴마다 조건을 평가하고 다른 하나는 목적을 유지한다. 그 차이가 루프가 스스로 멈출 수 있는지를 결정한다.
3. **상태 표기를 확인한다.** 연구 프리뷰 기능에는 안정된 API 계약이 없고, 그 위에 세운 루프는 그 불안정성을 물려받는다. 루프 정의 옆에 상태 표기를 적는다.
4. **의존한 한도를 기록한다.** 루프가 동시 에이전트 16개나 30분 체크인에 의존한다면, 그 숫자와 날짜를 루프 정의에 남긴다. 벤더 변경이 사고가 아니라 리뷰 항목으로 드러난다.
5. **로컬과 클라우드는 다른 루프다.** 로컬 간격 루프는 기기가 잠들면 멈추고, 클라우드 예약 작업은 계속 돌면서 계속 과금한다. 작업이 무엇에 의존하는지로 고르고, 어느 쪽인지 밝힌다.
6. **권한 모델을 이식하지 않는다.** 모드, 샌드박스 정책, 승인 정책은 일대일로 번역되지 않는다. 모드 이름이 아니라 샌드박스와 허용 목록에서 경계를 다시 도출한다.
