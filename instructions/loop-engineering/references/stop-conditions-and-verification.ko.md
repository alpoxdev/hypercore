# 정지 조건과 검증

> 영어판: [`stop-conditions-and-verification.md`](stop-conditions-and-verification.md)

루프는 그것을 끝내는 검사만큼만 좋다. 이 문서는 기계가 실패시킬 수 있는 조건을 쓰는 방법, 검사자를 배치하는 위치, 검사자의 정직함을 유지하는 방법을 다룬다.

## 조건은 목표가 아니다

| 형태 | 예 | 실패하는 이유 |
|---|---|---|
| 소망 | "더 좋게 만들어" | 측정할 수 없으니 실패할 수도 없다 |
| 목표 | "결제 흐름을 개선해" | 방향을 말할 뿐 종료 상태를 말하지 않는다 |
| 조건 | "`test/checkout`의 테스트가 모두 통과하고, `npm test`가 0으로 종료하며, 다른 테스트 파일은 수정되지 않는다. 20턴 뒤 중지" | 검사 가능하고, 상한이 있으며, 반증 가능하다 |

벤더 문서도 운용 수준에서 같은 구분을 한다. 여러 턴에 걸쳐 유효한 조건에는 "측정 가능한 종료 상태 하나", 에이전트가 그것을 어떻게 입증할지에 대한 "명시된 검사", 그리고 "중요한 제약" — 도달하는 동안 바뀌면 안 되는 것 — 이 있고, 턴이나 시간 조항을 덧붙일 수 있다(2026-11-03 확인). 조건 길이에도 상한이 있다. 그 한도를 문서화한 런타임에서는 4,000자다.

## 구성

| 필드 | 내용 | 빠졌을 때의 실패 |
|---|---|---|
| 종료 상태 | 측정 가능한 사실 하나. 테스트 결과, 종료 코드, 파일 수, 빈 큐 | 검사자가 사실을 읽는 대신 품질을 논쟁한다 |
| 검사 | 종료 상태를 입증하는 정확한 명령이나 산출물 | 에이전트가 다른 방식으로 입증하고 끝났다고 말한다 |
| 제약 | 바뀌면 안 되는 것. 건드리지 않을 파일, 바뀌지 않을 공개 API, 추가하지 않을 의존성 | 목표를 다른 것을 깨서 달성한다 |
| 상한 | 턴, 시간, 토큰 한도. 조건의 일부로 적는다 | 종료 상태에 도달할 수 없을 때 천장이 없다 |
| 에스컬레이션 | 검사를 돌릴 수 없거나 요구사항이 모호할 때 할 일 | 루프가 요구사항을 지어낸다 |

## 조건 예시

| 약한 조건 | 이유 | 더 강한 조건 |
|---|---|---|
| "실패하는 테스트를 고쳐" | 어느 테스트인지, 고칠 수 없으면 어떻게 하는지가 없다 | "`pytest tests/auth`가 0으로 종료하고 `src/auth/` 밖의 파일은 바뀌지 않는다. 10턴 뒤 중지" |
| "모듈을 정리해" | 반증 불가 | "`src/billing/`의 모든 파일이 400줄 미만이고, `bun test`가 0으로 종료하며, `index.ts`의 공개 export가 바뀌지 않는다" |
| "Lighthouse를 90 위로 올려" | 실행 회차와 URL이 불명 | "`/`의 Lighthouse 성능 점수가 연속 세 번 90 이상이고, 새 콘솔 오류가 없다. 5회 시도 뒤 중지" |
| "리뷰 코멘트를 처리해" | 큐는 조건이 아니다 | "PR에 미해결 리뷰 스레드가 0개이고 CI가 초록이다. 푸시할 때마다 다시 검사한다" |

세 번째 줄은 벤더의 예시 형태다. 에이전트가 감사를 실행해 점수를 출력할 수 있기 때문에, 도구를 실행할 수 없는 모델도 검사할 수 있는 조건이 된다(2026-11-03 확인).

## 검사가 도는 위치

| 배치 | 볼 수 있는 것 | 비용 | 쓰는 상황 |
|---|---|---|---|
| 작업 중인 에이전트 | 자기가 가진 모든 것 | 무료 | 유일한 검사로는 절대 쓰지 않는다. LE-S-1 |
| 도구 없는 별도 모델 | 에이전트가 대화에 드러낸 것만 | 턴당 작은 호출 한 번 | 종료 상태를 에이전트가 출력하고 증거가 텍스트일 때 |
| 도구를 쓰는 별도 모델 | 저장소, 명령, 환경 | 이터레이션마다 검증 작업 | 주장에 독립적 확인이 필요할 때 |
| 결정적 오라클 | 오라클이 측정하는 것 | 가장 싸다 | 테스트, 스키마, 종료 코드, 개수로 종료 상태를 표현할 수 있을 때 |
| 사람 | 모든 것과 판단 | 가장 비싸다 | 조건이 제품 수준이거나, 잘못된 판정의 비용이 클 때 |

도구 없는 검사자가 가장 과소평가된 배치다. 앞을 못 보는 것은 양날의 검이다. 저장소를 읽지 않으므로 저장소 상태가 판정을 흔들지 못하지만, 요약이 가진 전부이므로 그럴듯한 요약에는 속을 수 있다. 뒤쪽이 아래 표의 "그럴듯함 통과" 실패 모드이고, 조건을 쓸 때 에이전트가 성공을 주장하는 데 그치지 않고 자기 출력으로 입증하도록 써야 하는 이유다. 한계도 대칭이다. 에이전트가 출력하지 않은 것은 검사자에게 존재하지 않는다. 이 제약은 런타임 문서에 그대로 적혀 있다. 평가자는 "명령을 실행하거나 파일을 직접 읽지 않는다"(2026-11-03 확인).

## 판정 기계

불리언만 돌려주는 검사는 다음 이터레이션에 필요한 정보를 버린다. 판정과 이유를 함께 돌려준다.

| 판정 | 뜻 | 루프의 행동 |
|---|---|---|
| 아직 아님 | 조건이 성립하지 않고, 이유가 무엇이 빠졌는지 말한다 | 계속한다. 이유를 다음 턴에 넘긴다 |
| 충족 | 조건이 성립한다 | 루프를 해제하고 달성 항목을 기록한다 |
| 불가능 | 조건을 만족할 수 없다 | 루프를 해제하고 이유와 함께 실패 항목을 기록한다 |
| 평가 안 함(이 저장소 확장) | 백그라운드 작업이 아직 돌고 있어 턴이 완결 단위가 아니다 | 다음 완결 턴으로 평가를 미룬다 |
| 진전 없음(이 저장소 확장) | 도구 사용이나 상태 변화 없이 여러 턴이 지났다 | 멈추고 경고하며, 루프를 남긴 채 제어를 돌려준다 |

`아직 아님`, `충족`, `불가능`은 벤더 평가자가 돌려주는 세 가지 판정이다. `평가 안 함`과 `진전 없음`은 이 저장소의 확장이다. 조건이 아니라 러너의 상태를 보고하는 값이고, 아래에서 말하는 두 문제에 보고할 값을 주려고 두었다. 벤더가 보장하는 어휘가 아니라 이 저장소의 어휘로 읽는다.

이 기계를 동작하게 하는 세부가 셋이고, 재구현할 때 하나씩 빠지기 쉽다. `불가능`이 있어야 예산을 불가능 증명에 태우지 않는다. `평가 안 함`이 있어야 긴 서브에이전트 작업이 있는 루프가 미완결 턴으로 판정되지 않는다. `진전 없음`이 있어야 검사자에게 계속 답만 하면서 행동하지 않는 모델이 영원히 돌지 않는다.

## 실패 분류

실패한 턴은 한 덩어리가 아니다. 루프가 무엇을 할지 정하기 전에 분류한다.

| 실패 분류 | 예 | 루프의 행동 |
|---|---|---|
| 복구 불가, 운영자가 고쳐야 함 | 인증 실패, 크레딧 소진, 압축으로 해소되지 않은 컨텍스트 초과, 사용할 수 없는 모델 | 루프를 해제하고 원인을 밝히며, 다시 설정하라고 알린다 |
| 재시도 가능 | 서버 과부하, 끊긴 연결 | 자동 재시도. 세 번 뒤에는 일시정지 |
| 반복 가능, 기다리면 풀림 | 요청 한도, 구독 사용량 한도, 턴을 끝낸 훅 | 일시정지하고 원인을 밝히며, 한도가 풀리면 재개한다 |

복구 불가 네 분류는 `/goal`에 문서화돼 있다(2026-11-03 확인). 구체적 오류가 아니라 분류를 가져온다. 요점은 루프가 "세상을 고치고 나를 다시 준비시켜라"와 "기다려라"와 "다시 시도하라"를 구분해야 한다는 것이다. 셋을 하나로 합치면 실제 장애를 숨기거나, 재시도로 바뀌지 않을 일에 시도를 낭비한다.

## 검사자 구현

정지 검사는 턴이 끝날 때 도는 훅이다. 참조 구현은 프롬프트 기반 정지 훅이다. 런타임이 조건과 지금까지의 대화를 작은 고속 모델에 보내고, 모델이 판정과 짧은 이유를 돌려준다(2026-11-03 확인). 같은 런타임의 일반 훅 계약은 모델이 평가하는 `prompt` 유형을 지원하고, `$ARGUMENTS`로 훅의 JSON 입력을 받으며, 기본으로 백그라운드 모델을 쓰고, `{"ok": …}`와 이유를 돌려준다(2026-11-03 확인). 런타임에 그 계약이 있으면 루프의 검사를 그 위에 올린다. 없으면 이터레이션 안의 명시적 단계로 검사자를 돌린다.

이식해도 남는 구현 규칙이 셋이다.

1. 검사자는 세션 범위나 루프 범위를 가지며, 수명을 명시한다. 루프보다 오래 사는 검사는 놀라움이고, 루프 도중 조용히 사라지는 검사는 더 나쁘다.
2. 검사자의 모델을 이름으로 지정하고 교체 가능하게 둔다. 평가 토큰은 별도로 과금되며, 문서는 그것이 "본 턴 지출에 비해 대개 무시할 만하다"고 적는다. 검사자가 실제로 작을 때만 성립하는 주장이다(2026-11-03 확인).
3. 검사자의 판정을 메모리가 아니라 대화 기록에 남긴다. 루프가 판정받았다는 유일한 증거가 기록이다.

## 검사자의 정직함 유지

| 실패 | 증상 | 대응 |
|---|---|---|
| 자기 채점 | 에이전트 자신의 판단이 루프를 끝낸다 | LE-S-1. 다른 주체나 결정적 오라클 |
| 검사 연극 | 실제로 돌린 검사 없이 승인 | 검사자가 실행한 검사를 인용하게 한다 |
| 그럴듯함 통과 | 성공을 서술한 산문을 검사자가 받아들인다 | 종료 상태를 서사가 아니라 출력된 사실로 만든다 |
| 존재 확인 | "파일이 있다"가 "파일이 맞다"로 통과한다 | 존재가 아니라 내용과 동작을 검사한다 |
| 기준 표류 | 이터레이션마다 검사자의 기준이 움직인다 | 기준을 루프 정의에 고정하고 버전을 붙인다 |
| 동조 컨텍스트 | 검사자가 제작자의 추론을 물려받는다 | 검사자에게 새 컨텍스트를 준다. 제작자의 계획을 넘기지 않는다 |
| 표본 운 | 불안정한 검사가 한 번 통과해 루프가 멈춘다 | 불안정하거나 확률적인 검사에는 반복 증거를 요구한다 |

마지막 줄에서 루프 설계가 평가 설계와 만난다. 한 번의 관측은 판정이 아니다. 비결정적 판단을 다루는 반복과 집계 규칙은 [`../../harness-engineering/HARNESS_ENGINEERING.ko.md`](../../harness-engineering/HARNESS_ENGINEERING.ko.md)의 `HE-J-1`부터 `HE-J-7`까지에 있고, 그 규칙은 루프의 검사자에도 그대로 적용된다.

## 정체, 진동, 수렴

- **정체**: 이터레이션은 이어지는데 상태가 바뀌지 않는다. 반복되는 동일 상태 다이제스트, 도구 사용이 없는 턴, 같은 이유로 늘어나는 거부 횟수로 탐지한다. 형용사가 아니라 이름 붙인 상수로 상한을 둔다.
- **진동**: *n*번째 이터레이션이 *n−1*번째를 되돌린다. 연속 이터레이션의 diff를 비교해 탐지한다. 검사자는 양방향을 모두 승인하므로 멈추고 사람에게 넘긴다.
- **약한 수렴**: 매 이터레이션이 조금씩 개선되지만 조건이 성립하기 전에 예산이 끝난다. 정상적인 결과로 받아들이고, 조건까지의 거리와 함께 `exhausted`로 보고한다.
- **조기 수렴**: 작업이 줄어 조건이 자명하게 성립한다. 조건에 최소 범위를 넣어 막는다("`src/billing/*.ts`가 여전히 모두 export된다").

## 예산 소진과 에스컬레이션

소진은 네 필드를 갖는 보고 가능한 결과다. 어느 상한에 걸렸는지, 조건까지 얼마나 남았는지, 마지막 판정의 이유가 무엇이었는지, 재개를 위해 무엇이 저장됐는지다. 다음 중 하나면 에스컬레이션한다. 이 환경에서 조건을 검사할 수 없을 때, 요구사항이 모호하고 제품 수준일 때, 막고 있는 것을 루프가 바꿀 수 없을 때, 선언한 영향 범위를 넘어야 할 때다.

실무적인 에스컬레이션 정책은 세 단계다. 조용히 계속(정상), 멈추고 알림(재시도 가능하거나 대기), 멈추고 사람을 요구(검증 불가, 모호, 파괴적). 런타임의 상태 표기(활성, 일시정지, 해제, 달성, 실패)는 앞의 두 단계에 쓸 수 있는 어휘다(2026-11-03 확인).

## 이터레이션 기록

이터레이션마다 기록 하나를 남긴다. 없으면 루프를 디버깅할 수 없고 비용을 귀속시킬 수도 없다.

```yaml
iteration: 12
trigger: schedule | event:<source> | human | chained
condition: "pytest tests/auth exits 0 and no file outside src/auth/ changes"
verdict: not_yet_met | met | impossible | not_evaluated | no_progress
reason: "2 of 5 tests fail in src/auth/session.py"
turns: 4
tokens: {input: 0, output: 0, cached: 0}
changed_paths: []
checker: {kind: model_no_tools | model_with_tools | oracle | human, model: "..."}
stop_cause: condition_met | budget | no_progress | error | human
```
