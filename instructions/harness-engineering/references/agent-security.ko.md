## 두 원칙

**least agency**(최소 자율) — 최소 권한의 에이전트판이다. 에이전트가 접근할 수 있는 범위뿐 아니라
확인 없이 행동할 자유까지 제한한다. 자율성은 기본값이 아니라 획득되는 것이다.

**strong observability**(강한 관측성) — 에이전트가 무엇을, 왜, 누구의 정체성으로 하는지 보여야 한다.
관측성 없는 최소 자율은 맹목적 위험 감소이고, 최소 자율 없는 관측성은 무제약 에이전트에 대한 감시다.

## 위험 10종 (ASI01~ASI10)

| id | 위험 | 완화 주제 |
|---|---|---|
| ASI01 | 에이전트 목표 탈취 | 외부 입력을 지시가 아니라 데이터로 취급, 계획을 허용 행동 목록으로 검증, 탈취된 목표가 프로덕션에 닿지 못하게 샌드박스 |
| ASI02 | 도구 오용과 악용 | 도구 범위 축소, 인자 스키마 검증, 호출마다 정책 적용, 이상 도구 사슬 감시, 쓰기가 불필요하면 읽기 전용 |
| ASI03 | 에이전트 정체성·권한 남용 | 전용 에이전트 정체성과 기한 있는 최소 권한 범위, 도구 수준 인가, 에이전트·사용자·행동을 잇는 감사 기록 |
| ASI04 | 에이전트 공급망 취약점 | 도구 버전 고정·검증, MCP·플러그인 출처 인증, 템플릿 무결성 검사, 서드파티 도구 격리, 전이 의존성 감사 |
| ASI05 | 예기치 않은 코드 실행 | 생성된 코드를 프로덕션 자격증명으로 실행하지 않기, 최소 권한 샌드박스, 실행 전 허용 목록 |
| ASI06 | 메모리·컨텍스트 오염 | 저장 전 정제, 저장소 무결성 검사, 에이전트별 메모리 범위, 이상 쓰기 감시, 롤백 경로 유지 |
| ASI07 | 안전하지 않은 에이전트 간 통신 | 모든 메시지 인증, 에이전트별 키로 서명, 논스·타임스탬프, 위임 사슬 인가, 에이전트 간 권한 상승 금지 |
| ASI08 | 연쇄 실패 | 회로 차단기, 계획과 실행 사이 검증, 롤백, 체인 깊이·런타임 상한, 자기 강화 오류 패턴 감시 |
| ASI09 | 인간-에이전트 신뢰 악용 | UI에서 에이전트 내용과 검증된 데이터를 구분, 고위험 행동에 사람 승인, 권고에 출처 표시 |
| ASI10 | 통제 이탈 에이전트 | 정체성별 행동 기준선, 시간에 걸친 이상 탐지, 킬 스위치, 세션 격리, 드리프트 감시 |

## 위험들이 공통으로 갖는 것

ASI01~ASI10을 가로질러 패턴이 반복된다. 많은 실패가 **정체성과 인가 문제로 위장**해 있다. 목표
탈취는 에이전트가 신뢰된 오케스트레이션과 신뢰할 수 없는 데이터를 구분하지 못할 때 성공한다. 도구
오용은 인가를 도구가 아니라 에이전트에서 검사할 때 성공한다. 통제 이탈 에이전트는 검증된 정체성에 묶인
행동 기준선이 없을 때 성공한다.

모든 신뢰 경계에서 물을 세 가지:

1. **누가 행동하는가?** 빌려온 사람 세션이 아니라 구분된 에이전트 정체성.
2. **무엇이 허가되어 있는가?** 범위가 있고 기한이 있으며 취소 가능한 권한.
3. **나중에 증명할 수 있는가?** 정체성·정책 결정·결과를 잇는 감사 기록.

하네스 규칙이 직접 규정하는 지점은 **조합**이다. 개별 도구는 허용되어도 그 사슬은
허용되지 않을 수 있다.
