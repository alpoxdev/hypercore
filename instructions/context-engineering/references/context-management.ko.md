# Context Management

> 영어판: [`context-management.md`](context-management.md)

오래 도는 에이전트가 쓸 만한 컨텍스트를 유지하는 방법을 다룬다. 무엇을 창밖으로 옮기고, 무엇을 비우고, 무엇을 요약하고, 무엇을 작업자별로 나눌지 정한다. 기제와 벤더별 파라미터는 이 파일이 맡고, 계약은 [`../CONTEXT_ENGINEERING.ko.md`](../CONTEXT_ENGINEERING.ko.md), 예산이 왜 중요한지는 [`core-principles.ko.md`](core-principles.ko.md)가 맡는다.

## 1. 증상에서 시작

| 증상 | 수단 | 먼저 확인할 것 |
|---|---|---|
| 도구 호출 하나가 창을 범람시킨다(로그 덤프, 파일 전체) | 결과를 지우고 참조만 남긴다 | 경로나 URL이 남아 다시 읽을 수 있는가 |
| 세션이 몇 시간씩 이어지며 품질이 흐트러진다 | 압축 | 계획이 창 밖에 있고, 요약 뒤에 다시 읽히는가 |
| 모델이 앞서 나온 틀린 가정을 되풀이한다 | 해당 턴을 고쳐 쓰거나 뺀다 | 정정이 기록되었는가, 한 번 말하고 끝났는가 |
| 출력은 늘어나는데 정확도는 떨어진다 | 압축과 선택 | 검색 범위가 좁은가, 만약을 대비해 전부 올렸는가 |
| 독립적인 조사가 여러 갈래다 | 격리 | 작업자들이 결정을 공유하는가, 질문만 공유하는가 |
| 압축이 반복되는데 곧바로 다시 찬다 | 선택 | 원인이 대형 파일이나 도구 출력 하나인가 |

컨텍스트 창을 키우는 것으로는 이 증상이 해결되지 않는다. 작업 난이도를 고정해도 입력 길이가 늘면 성능이 떨어진다(Chroma, 모델 18종, 2025-07-14). 이 하락은 과제가 어려워져서 생긴 것이 아니다.

## 2. 요약보다 먼저 상태를 옮긴다

요약은 세부를 잃고 파일은 잃지 않는다. 살아남아야 하는 부분을 먼저 오래 남는 자리에 쓴 다음, 남은 것을 요약한다.

- 계획, 미해결 질문, 검증 상태는 에이전트가 다시 읽는 파일에 두고 대화에 두지 않는다.
- 모든 압축은 복원 가능하게 만든다. 웹 페이지 내용은 URL이, 문서 내용은 경로가 남아 있을 때만 버린다(Manus, 2025-07-18).
- 목표를 컨텍스트 끝자락에서 다시 읽게 한다. Manus는 `todo.md`를 계속 고쳐 써서 전체 계획을 창 중간이 아니라 최근 주의 구간에 둔다.
- 압축 뒤에는 다음 행동 전에 계획 파일을 다시 읽는다. Anthropic은 지나치게 공격적인 압축이 “나중에야 중요성이 드러나는 미묘하지만 결정적인 맥락”을 잃을 수 있다고 적는다.

## 3. 선택은 좁게

- Anthropic은 “기능을 지나치게 많이 덮거나 어느 도구를 써야 할지 모호한 지점을 만드는 비대한 도구 집합”을 가장 흔한 실패 유형으로 꼽는다. 판단 기준도 제시한다. 사람 엔지니어가 상황별로 어느 도구를 써야 하는지 확정하지 못하면 모델도 마찬가지다.
- 쓸 수 없는 도구는 요청에서 지우기보다 마스킹한다. 도구 정의는 직렬화된 컨텍스트 앞부분에 놓이므로 실행 중에 지우면 캐시 접두부가 무효가 된다(Manus, “지우지 말고 가린다”).
- 참조 자료는 세션 시작이 아니라 그 자료가 필요한 단계에서 읽는다. 루트의 지도와 필요할 때의 읽기가 항상 켜 둔 큰 묶음보다 낫다.

## 4. 압축은 세 단계

| 단계 | 기제 | 비용 | 쓰는 때 |
|---|---|---|---|
| 1 | 오래된 도구 결과를 지우고 호출 기록은 남긴다 | 가장 싸고, 무엇을 실행했는지 보존된다 | 다시 가져올 수 있는 장황한 도구 출력 |
| 2 | 대화를 요약해 새 창을 연다 | 모델 호출 1회 추가, 세부 손실 | 창 한계에 근접했을 때 |
| 3 | 서면 브리핑과 함께 새 세션으로 인계한다 | 적히지 않은 것은 모두 잃는다 | 단계 경계, 또는 요약 자체가 창을 채웠을 때 |

규칙:

1. **재현율 먼저, 정밀도 나중.** Anthropic의 지침은 관련된 것을 모두 잡도록 압축 프롬프트를 쓰고, 그다음 불필요한 것을 덜어내며 정밀도를 올리는 순서다.
2. **살아남을 것을 이름으로 적는다.** 결정, 미해결 버그, 파일 경로, 다음 행동이다. 중복된 도구 출력과 확인 응답은 버린다.
3. **실패를 정리하지 않는다.** Manus는 “오류 복구가 진짜 에이전트 동작을 보여 주는 가장 분명한 지표 가운데 하나”라는 이유로 잘못된 시도를 남긴다. 실패를 지우면 그 접근을 버렸다는 증거도 함께 사라진다.
4. **캐시를 예산에 넣는다.** 압축은 이력을 더 짧은 새 접두부로 바꾸므로 대화 계층의 캐시는 설계상 무효가 된다. 단계마다 압축하지 말고 압축 사이에 작업을 모아서 처리하며, 유휴 세션을 이어받을 때 압축 비용이 가장 크다는 점을 예상한다.
5. **반복을 멈춘다.** 입력 하나가 요약 직후 창을 다시 채운다면 압축을 또 하지 말고 그 입력을 고친다.

교훈이 되는 잘못은 남기고, 길고 복원 가능한 부분은 요약한다. 사실의 유일한 사본은 절대 요약하지 않는다.

## 5. 공유보다 격리

격리는 측정된 효과가 가장 크고 문헌의 의견 차이도 가장 큰 수단이다.

- 기제는 세 가지다. 자체 컨텍스트 창을 가진 서브에이전트가 요약만 돌려주는 방식, 샌드박스가 코드를 실행하고 값만 돌려주는 방식, 병렬 작업마다 별도 컨텍스트 브랜치를 두는 방식이다.
- Anthropic은 에이전트가 채팅의 약 4배, 멀티 에이전트가 약 15배의 토큰을 쓴다고 보고한다. BrowseComp에서 토큰 사용량만으로 성능 분산의 80%가 설명됐고, 리드 에이전트와 서브에이전트 조합이 내부 리서치 평가에서 단일 에이전트를 90.2% 앞섰다(2025-06-13). 모두 벤더 자체 평가이므로 얻을 수 있는 이득의 상한으로 보고, 기본 기대값으로 삼지 않는다.
- Cognition은 병렬 쓰기 에이전트에 대해 반대 입장을 취한다. 두 번째 원칙이 “행동은 암묵적 결정을 동반하고, 상충하는 결정은 나쁜 결과를 낳는다”이다. 서로의 행동을 보지 못하는 서브에이전트는 일관되지 않은 작업을 만들므로, 전용 압축 모델을 둔 단일 스레드 에이전트를 권한다(2025-06-12).
- 이견은 벤더가 아니라 작업 모양으로 갈린다. 결과가 글로 합쳐지는 **조사**(폭넓은 탐색, 서로 다른 검토 관점, 장황한 분류)는 격리한다. 일관성이 필요한 **결정**은 격리하지 않고, 두 작업자가 양립하지 않는 반쪽을 만들 수 있는 코드 작성도 격리하지 않는다.
- 인계에는 목표, 지금까지 확인한 제약, 출력 스키마, 중단 조건이 들어간다. 작업 문구만 복사하는 것은 컨텍스트가 아니다. 부모의 도구 호출이 암묵적 결정을 담고 있기 때문이다.

## 6. 메모리는 저장소이지 권위가 아니다

- Anthropic의 메모리 도구는 클라이언트 측 파일 기반 디렉터리이며, 모델이 정해진 명령 집합(`view`, `create`, `str_replace`, `insert`, `delete`, `rename`)으로 고치고 애플리케이션이 그 연산을 실행한다. 문서상 정식 제공 상태이며 베타가 아니다.
- 표면이 무엇이든 메모리 내용은 검색된 데이터다. 나이를 가진 근거로 컨텍스트에 들어오며 지시로 들어오지 않는다. 오래된 메모가 현재 요청을 덮어써서는 안 된다([`runtime-profiles.ko.md`](runtime-profiles.ko.md) 6번 규칙).
- 메모리를 쓴 시점을 남긴다. 나중에 읽는 쪽이 결정과 뒤집힌 추측을 구분할 수 있어야 한다.

| Google ADK | `EventsCompactionConfig`의 `token_threshold`, `event_retention_size`, `overlap_size`, `compaction_interval`. 둘 다 설정하면 토큰 기반이 우선한다 | 세션 이벤트는 영구 로그에 남고 프롬프트로 보이는 부분만 줄인다 | 세션과 분리된 메모리 계층, 이름으로 참조하는 아티팩트 |
| Claude Code | `/compact [지시]`, 모델별 창에 따른 자동 압축(`/autocompact 500k`로 조정). 요약 뒤 최근 수정 파일 5개까지 다시 읽는다 | 오래된 도구 결과를 컨텍스트에서 지운다 | `CLAUDE.md`와 자동 메모리는 압축 뒤 디스크에서 다시 주입된다 |
| Claude Agent SDK | 자동 압축 시 `compact_boundary` 시스템 메시지를 낸다. 수동은 `/compact`를 프롬프트 문자열로 보낸다. `PreCompact`·`PostCompact` 훅(트랜스크립트 보관이 문서화된 용도) | Claude Code와 같다 | 세션은 대화를 보존하고 파일 시스템은 보존하지 않는다 |

모델과 버전 제외 조건은 벤더 문서에 있다. 이 표를 믿지 말고 그쪽에서 확인한다. Anthropic의 압축 방식은 일부 구형 모델을 제외하고, Google의 명시적 캐시 객체는 최신 세대에서 쓸 수 없다.

## 8. 점검 목록

- [ ] 권위 있는 계획이 창 밖에 있는가
- [ ] 모든 압축을 경로·URL·id로 되돌릴 수 있는가
- [ ] 압축 프롬프트가 결정, 미해결 버그, 다음 행동을 지정하는가
- [ ] 압축 발동 지점을 추정하지 않고 측정했는가
- [ ] 병렬 작업자가 결정을 공유하는가, 질문만 공유하는가
- [ ] 검색된 메모리에 작성 시점이 붙어 있는가
- [ ] 요약 뒤에 버린 자료가 유일한 사본이 아니었음을 누군가 확인했는가
